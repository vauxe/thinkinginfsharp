# 规格：F# 思维 / Thinking in F#

- 状态：已批准
- 日期：2026-08-24
- 交付物：中英文双语静态书籍网站
- 首版验证基线：F# 10、.NET 10 LTS

## 1. 目标

建设一本帮助有命令式或面向对象编程经验的开发者学习并掌握 F# 的书。它不以“列出语法特性”为终点，而要让读者形成以下能力：

1. 把现实问题表达为值、类型和函数；
2. 用代数数据类型刻画状态，主动排除非法状态；
3. 用组合构造程序，并清楚地区分纯逻辑与副作用；
4. 编写可测试、可维护、可诊断的生产级 F#/.NET 软件；
5. 与 C# 和 .NET 生态自然协作；
6. 判断 F# 在 Web、数据、云、桌面、自动化和 Unity 等方向中的适用性与限制。

本书借鉴 *Think Python* 的教学形式：概念逐步展开、术语在首次出现时解释、案例穿插、调试提示、章末词汇与练习。章节顺序、概念主线、示例和文字均从 F# 本身重新设计，不翻译或改写 *Think Python*。

## 2. 目标读者

### 2.1 默认前置知识

读者通常至少使用过 C#、Java、Python 或 JavaScript 中的一门语言，并理解：

- 函数调用、条件判断和循环；
- 基本集合；
- 模块、类或包的基本用途；
- 命令行的最基本操作。

本书不假定读者学过函数式编程、类型理论或领域驱动设计。

### 2.2 阅读完成后的能力

完整读者应能：

- 独立创建并组织 F# 项目；
- 阅读类型签名并利用类型推断，而不是与编译器对抗；
- 用记录、可辨识联合和模式匹配设计领域模型；
- 在 `option`、`Result`、异常和验证累积之间作出有理由的选择；
- 正确使用集合、递归、折叠和函数组合，并解释急切求值、惰性求值与重复枚举的差异；
- 正确处理 I/O、资源、异步、并发、取消和错误传播；
- 在 F# 与 C#/.NET 交界处显式处理引用空值、可空值类型和异常；
- 编写示例测试与性质测试；
- 设计面向 F# 或跨 .NET 语言的公共 API；
- 衡量性能后再选择数组、序列、可变状态、结构体或其他优化手段；
- 完成一个包含领域、持久化、Web 边界和外部服务的应用。

## 3. 非目标

首版明确不包含：

- PDF、EPUB 或印刷排版；
- 对 *Think Python* 或其他书籍的翻译、逐章映射或练习改写；
- 零编程基础课程；
- 对每个 .NET 框架或第三方库的穷尽式参考；
- 把范畴论术语作为理解基础语法的前置条件；
- 为展示“函数式技巧”而使用晦涩的无点风格、自定义运算符或过度抽象；
- 绑定 GitHub Pages、Cloudflare Pages、Netlify 等特定托管平台；
- 在没有测量数据时给出绝对化的性能结论。

## 4. 教学原则

### 4.1 从 F# 的语言观出发

全书的第一单位是“表达式产生值”，而不是“变量保存数据”。教学顺序遵循以下依赖：

```text
表达式与值
    ↓
函数与类型推断
    ↓
模式匹配与集合变换
    ↓
记录与可辨识联合
    ↓
类型驱动建模
    ↓
组合、模块与边界
    ↓
副作用、异步与并发
    ↓
工程化、互操作与生态
```

与 C#、Java、Python 或 JavaScript 的比较只用于拆除已有误解，不能决定章节结构。

### 4.2 先遇到问题，再引入抽象

每个非平凡概念都遵循：

1. 一个具体问题；
2. 最直接但存在局限的解法；
3. F# 提供的语言构造；
4. 类型和运行行为的解释；
5. 适用边界与常见误用；
6. 可运行练习。

计算表达式、性质测试、代理和性能优化等主题必须先有实际需求，再给名称和一般化解释。

每章还必须声明前置概念。新章节可以短暂使用下一章才正式展开的语法，但必须就地给出足以阅读示例的最小解释，不能让核心推理依赖尚未教授的知识。

### 4.3 简洁不等于省略推理

- 每节只承担一个主要概念；
- 删除不改变理解或决策的信息；
- 保留类型推断过程、求值过程、失败路径和设计取舍；
- 同一事实只在首次出现时完整解释，后文使用链接回指；
- 不用“显然”“简单地”掩盖推理步骤。

### 4.4 可实验

读者应能从 F# Interactive 小实验开始，逐步进入脚本、项目、测试和完整应用。正文中的有效代码默认来自仓库内受验证的源文件，而不是散落在 Markdown 中的未测试副本。

## 5. 技术栈

| 范围 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | F# 10 | 当前稳定语言版本，与 .NET 10 一起发布 |

| JavaScript 运行时 | Node.js `>=22` | 满足 VitePress 当前文档要求 |
| 包管理 | pnpm `11.7.0` | 锁文件、速度和可复现安装 |
| F# 格式化 | Fantomas，版本在实现时锁定 | F# 社区标准格式化器，默认风格与官方指南一致 |

## 6. 命令契约

实现后的仓库必须提供以下稳定命令：

```sh
# 安装网站依赖
pnpm install --frozen-lockfile

# 本地阅读与编辑
pnpm dev

# 构建静态站点
pnpm build

# 预览构建结果
pnpm preview

# 检查中英文页面、标题、章节和练习是否成对
pnpm check:parity

# 检查 Markdown 元数据、内部链接和术语使用
pnpm check:content

# 编译并测试全部 F# 示例
pnpm check:examples

# 运行全部质量门
pnpm test
```

`pnpm test` 至少依次执行内容一致性检查、F# 构建与测试、静态站点构建。任何一步失败都返回非零状态。

底层 F# 命令保持可单独运行：

```sh
dotnet restore ThinkingInFSharp.slnx
dotnet build ThinkingInFSharp.slnx --configuration Release --no-restore
dotnet test ThinkingInFSharp.slnx --configuration Release --no-build
dotnet fsi --exec <script.fsx>
```

## 8. 双语设计

### 8.1 路由与切换

- `/` 是语言中立的入口，只提供中英文介绍与选择；
- `/zh/` 和 `/en/` 分别是两种语言的首页；
- 对应页面必须使用相同相对路径，例如：
  - `/zh/part-02/discriminated-unions`
  - `/en/part-02/discriminated-unions`
- 语言切换器根据相对路径跳转，不把读者送回首页；
- 页面分别设置 `lang="zh-Hans"` 与 `lang="en"`；
- 导航、搜索界面、无结果提示、上一章和下一章均本地化；
- 两种语言分别建立本地搜索索引，避免混合结果。

### 8.2 页面身份

每个正文页面具有相同的稳定身份：

```yaml
---
translationKey: part-02/discriminated-unions
kind: chapter
part: 2
chapter: 8
status: draft
verifiedWith:
  fsharp: "10"
  dotnetSdk: "10.0.301"
---
```

路径与 `translationKey` 在两种语言中一致；标题、摘要和正文分别使用自然的中文或英文。

### 8.3 一致性定义

“中英文保持一致”指：

- 学习目标、标题层级和概念顺序一致；
- 有相同的示例、图、提示、警告、练习和答案；
- 事实、限制条件与来源一致；
- 不要求逐句直译，允许为语言自然度调整句序、比喻和解释长度；
- 任一语言不能成为另一语言的摘要版。

自动检查负责结构一致性，人工审阅负责语义一致性。单语言草稿可以短暂存在于工作分支，但不能标记为完成或进入发布构建。

### 8.4 术语

仓库维护一份带稳定标识的双语术语表。首次出现术语时给出简明定义；后续统一使用同一译法。无法自然翻译的 F#/.NET 专有名词保留英文，并在中文首次出现时解释。

例如：

| ID | 中文 | English |
| --- | --- | --- |
| `binding` | 绑定 | binding |
| `discriminated-union` | 可辨识联合 | discriminated union |
| `partial-application` | 部分应用 | partial application |
| `computation-expression` | 计算表达式 | computation expression |

## 9. 内容架构

### 前言

- 本书适合谁、不适合谁；
- 三条阅读路线：快速入门、系统学习、C#/.NET 转向 F#；
- 如何运行示例、阅读类型签名和使用练习；
- F# 10 与 .NET 10 验证范围。

### 第一部分：表达式、值与函数

1. 第一次 F# 会话：FSI、脚本、项目、字面量、字符串与 `unit`；
2. 值、绑定、表达式、基本类型与类型推断；
3. 函数也是值：命名与匿名函数、应用、高阶函数、柯里化、元组参数和部分应用；
4. 从布尔判断到基本模式：`if`、`match`、元组与列表解构；
5. 列表变换、管道与数据流，并对比 `for`、`while` 和可变绑定；
6. 递归、尾递归与折叠。

目标：读者不再把 F# 当成“少写括号的 C#”，能够从表达式、类型签名、输入输出和数据变换理解小程序。第 3 章只建立自动泛化的直觉；值限制和显式泛型约束留到第 11 章。

### 第二部分：用类型建立模型

7. 元组、记录、匿名记录、不可变更新、结构相等与结构比较；
8. 可辨识联合、状态建模与完整的穷尽模式匹配；
9. `option` 与 `Result`：分别表达缺失和预期失败；
10. 递归类型、树和结构递归；
11. 泛型、自动泛化、值限制、相等/比较约束与度量单位；
12. 私有表示、伴生模块、智能构造函数与“让非法状态无法表示”。

目标：读者能把一组松散字段改造为能表达业务规则并保护不变量的类型系统。第 7、11 章贯通结构相等、结构排序、引用身份、哈希相等及组成类型约束，并为第 14 章的 `Map`/`Set` 键规则作准备。第 9 章指出 `Some null` 仍然可能存在；完整的 .NET 空值边界留到第 19 章。第 12 章在使用私有表示时就地教授必要的模块作用域和访问控制语义，不等待第 16、17 章。

### 第三部分：组合与程序结构

13. 函数组合、参数顺序与面向管道的 API；
14. 集合选择与求值：`list`、`array`、`seq`、`Map`、`Set`、转换成本和重复枚举；
15. 活动模式与面向领域的匹配边界；
16. 模块、命名空间、文件顺序、项目结构与编译器设置；
17. 签名文件、访问控制、封装和面向 F# 的 API；
18. 用显式函数组合工作流并累积验证错误。

目标：读者能组织多文件代码，并理解抽象如何从重复的组合模式中产生。第 14 章明确区分急切与惰性求值、`seq` 中副作用和重复枚举，以及有序 `Map`/`Set` 与哈希集合的不同约束；第 16 章启用 `<Nullable>enable</Nullable>` 并解释由此产生的最小类型标注；第 18 章不假定 FSharp.Core 存在内置 `Result` 或验证构建器，先用普通函数解释失败短路与错误累积。`seq`、`async`、`task` 等内置计算表达式在各自问题出现时讲解；自定义构建器和构建器特定的 `and!` 语义只作为高级延伸。

### 第四部分：副作用、异步与并发

19. 从 F# 使用 .NET API 与空值边界：构造、成员、重载、接口、`T | null`、`Nullable<T>` 与边界转换；
20. 函数式核心与副作用边界：时间、随机性、环境和显式依赖；
21. 异常、资源生命周期、`use` 与文件/网络 I/O；
22. `Async<'T>` 与 `Task<'T>`：两种执行模型及互操作选择；
23. 组合异步工作：取消、超时、错误和资源传播；
24. 并行、并发、代理、共享状态、受控可变性与缓存。

目标：读者能在不假装“现实世界没有副作用”的前提下，保持核心逻辑可推理、可测试。第 19 章在任何实质性 .NET I/O 前完成引用空值、可空值类型和 `option` 转换模型；第 21 章用决策表收束 `option`、`Result`、验证累积与异常的边界；第 22 章明确 `Async<'T>` 描述尚待启动的工作，而 `task {}` 立即开始执行；第 23 章证明取消令牌必须显式传播，并覆盖“取消操作”与“只放弃等待”的区别、故障传播以及成功/失败/取消路径中的同步和异步释放。配置和序列化在贯穿项目的真实边界中教授，不作为彼此无关的 API 清单。

### 第五部分：.NET 互操作与工程质量

25. 在 F# 中定义对象：类、成员、接口、对象表达式、类型扩展和结构体；
26. 深入 .NET 边界：运行时类型、转换、委托、事件、集合、身份与哈希；
27. 设计给 C# 调用的 F# API：公共表示、属性、文档和兼容性；
28. 示例测试、测试替身与边界测试；
29. 使用 FsCheck 进行性质测试；
30. 编译器诊断、调试、格式化、静态分析与可复现构建；
31. 先测量再优化：分配、集合、内联、剖析及低层特性的适用边界；
32. 从函数到应用：依赖、端口、工作流、配置、生命周期和最小可观测性。

目标：读者能写出团队可维护、能与现有 .NET 系统共存的代码。第 30 章只教授持续检查和可复现构建的原则，不扩展为 CI/CD 平台教程；第 31 章仅让读者在测量驱动的语境中识别 `voption`、`byref`/Span、裁剪和预先编译（AOT）；第 32 章只覆盖足以诊断示例应用的结构化日志、指标和追踪概念。

### 第六部分：贯穿项目——活动预约系统

活动预约系统不是到本部分才突然出现：第一部分用它练习输入与数据变换，第二部分建立领域类型和不变量，第三部分组合纯工作流，第四部分连接异步端口，第五部分补齐测试和跨语言边界。本部分负责把这些小切片组装成应用。

33. 收束业务语言、命令、事件和领域模型；
34. 组装纯预约工作流与验证规则；
35. 用端口连接本地持久化、配置、边界 DTO、支付替身和通知；
36. 暴露 Web API，并处理 JSON 契约、输入边界、异步、取消和机密配置；
37. 用持久化策略处理原子容量约束、幂等、重试和部分失败；
38. 完成集成测试、运行时诊断、C# 契约客户端与发布检查。

## 10. 章节模板

核心章节默认包含：

```text
1. 前置概念、本章问题与学习目标
2. 最小实验
3. 概念展开
4. 类型或求值过程如何约束程序
5. 贯穿案例或工程连接
6. 常见误解与编译器提示
7. 何时使用、何时不用
8. 小结
9. 术语
10. 练习（理解、修改、迁移或设计）
11. 来源与验证版本
```

不是每章都强制凑齐所有栏目。短生态导览可以省略不相关栏目，但两种语言的结构必须相同。每一部分至少有一道迁移练习，要求读者把方法应用到正文未出现的新问题，避免只会复述示例。

练习答案规则：

- 封闭题给出可运行答案；
- 设计题给出评审标准和至少一种参考方案，不伪装成唯一答案；
- 答案与正文共用经过验证的示例；
- 需要先思考的答案放在独立页面，不紧贴题目泄露。

## 11. 文字与代码风格

### 11.1 中文

- 使用简体中文和现代技术书面语；
- 句子优先短而完整；
- 避免未经解释的英文缩写和生硬直译；
- 中文标点与英文代码之间保持一致空格规则；
- 同一术语只使用术语表中的首选译法。

### 11.2 English

- Use direct, idiomatic technical English;
- Prefer short sentences without reducing conceptual precision;
- Do not preserve Chinese word order or culture-specific metaphors mechanically;
- Define F# terms on first use and use them consistently thereafter;
- Treat the English edition as a complete book, not as translation notes.

### 11.3 F#

代码遵循官方 F# 风格指南和 Fantomas 默认格式。局部值与函数使用 `camelCase`，类型、联合用例与模块使用 `PascalCase`。仅在边界、教学需要或推断不清晰时显式标注类型。

```fsharp
namespace ThinkingInFSharp.Booking

open System

type ReservationRequest =
    { EventId: Guid
      AttendeeId: Guid
      Seats: int }

type ReservationEvent =
    | SeatsReserved of ReservationRequest

type ReservationError =
    | InvalidSeatCount of int
    | NotEnoughSeats of available: int * requested: int

[<RequireQualifiedAccess>]
module Reservation =
    let decide availableSeats request =
        if request.Seats <= 0 then
            Error(InvalidSeatCount request.Seats)
        elif request.Seats <= availableSeats then
            Ok(SeatsReserved request)
        else
            Error(NotEnoughSeats(availableSeats, request.Seats))
```

风格约束：

- 优先展示清楚的中间值，不追求无点风格；
- 不为单一用途定义自定义运算符；
- 不在没有性能证据时使用 `struct`、`voption` 或暴露可变状态；
- 金额示例使用 `decimal` 与明确货币类型，不使用二进制浮点数代替金额；
- 时间边界优先使用 `DateTimeOffset`、`TimeProvider` 或领域类型；
- 公共边界显式处理 `null`、异常和取消；
- 示例中的省略号只能出现在明确标注为“片段”的代码块中。

## 12. 正确性与来源策略

### 12.1 来源优先级

语言和生态事实按以下顺序核验：

1. F# 语言规范、正式 RFC 和 FSharp.Core API；
2. Microsoft Learn 的 F#/.NET 官方文档；
3. 对应框架或库的官方文档与版本说明；
4. 在目标 SDK 上实际编译、运行和测试的结果。

博客、问答网站和模型记忆不能作为非平凡技术结论的唯一来源。社区资料可以提供背景，但必须与官方资料或运行证据交叉核验。

### 12.2 版本声明

- 语言核心以 F# 10 / .NET 10 为基线；
- Unity 导览以 Unity 6.3 LTS、`.NET Standard 2.1` API Compatibility Level 为基线，并记录实际人工验证所用的编辑器补丁版本；
- 版本相关的语法、API、性能或兼容性结论在页面末尾注明验证版本；
- 生态章节列出第三方包的确切版本；
- 预览功能不得写成稳定功能；若确有教学价值，放入明确的“预览”提示框；
- 当官方文档与实际行为不一致时，记录差异和复现命令，不静默选择一种说法。

### 12.3 事实与观点

- “编译器如何工作”“API 是否支持”属于事实，必须验证；
- “何种设计更易维护”属于有条件的建议，必须给出条件和代价；
- 不使用“函数式总是更安全”“不可变一定更快”等绝对表述；
- 性能章节必须给测量环境、基准方法和结果限制。

## 13. 示例系统

### 13.1 单一代码来源

中英文页面引用 `examples/` 中的同一源文件或同一区域。正文不复制两份独立 F# 代码，从结构上避免翻译时产生代码漂移。

### 13.2 示例分类

| 分类 | 要求 |
| --- | --- |
| `script` | `dotnet fsi --exec` 成功并验证关键输出 |
| `compile` | 属于解决方案，Release 构建无警告；需要行为证据的可执行项目还要用参数数组运行并验证有序输出 |
| `test` | 由 `dotnet test` 验证行为和边界 |
| `contract` | 验证 DTO/JSON 往返、F#/C# 互操作或其他跨边界稳定表示 |
| `unity-plugin` | 以 `netstandard2.1` 构建并包含 `FSharp.Core` 装配说明；Unity 导入与 Player 构建结果单独记录 |
| `expected-error` | 验证编译失败及预期诊断编号，用于教授错误信息 |
| `illustrative` | 仅在无法独立执行时使用，并在页面显著标注省略边界 |

有效示例默认启用警告即错误。故意不穷尽的模式匹配或其他警告只能存在于 `expected-errors/`，不能通过全局关闭警告掩盖。

### 13.3 输出与平台

- 输出示例尽量确定性；
- 时间、随机数、区域设置和文件路径必须被控制或明确说明；
- 核心示例在 Windows、macOS 和 Linux 上使用相同命令；
- 平台专属内容放在明确的生态章节中，不污染核心学习路径。

## 15. 项目边界

### 始终执行

- 先查官方资料，再写版本相关内容；
- 代码改动后运行与改动范围相称的检查；
- 一次提交一个完整的双语章节或基础设施切片；
- 两种语言共用代码、图和稳定页面身份；
- 记录第三方包版本和验证日期；
- 保持静态输出，不要求服务器端功能。

### 先询问

- 更换静态站点生成器或测试框架；
- 改变目标 F#/.NET 主版本；
- 新增需要账号、密钥或外部托管服务的功能；
- 删除或合并已确认的篇章；
- 将某一语言设为次要版本；
- 引入会显著增加客户端 JavaScript 的交互框架。

### 永不执行

- 提交密钥、访问令牌或个人数据；
- 复制受版权保护书籍的大段文字、练习或图；
- 用不可编译的代码冒充可运行示例；
- 静默忽略中英文差异或失效测试；
- 为迎合篇幅而重复解释同一概念；
- 将预览 API 表述为稳定承诺。

项目首版完成时，必须同时满足：

1. 静态站点可由全新环境依照 README 中的命令构建；

## 18. 已采用的设计决定

以下决定来自已确认的用户意图：

- 只交付静态网站；
- 中英文均为完整正文，并服务只会其中一种语言的读者；
- 核心面向已有编程经验但缺少函数式背景的开发者；
- 以 F# 自身的思维方式组织全书；
- 终点是生产级建模与工程能力；
- 可以发散介绍 .NET、Unity 等生态，但不喧宾夺主；
- 正确与简洁是硬性质量约束。

以下决定仍需通过本规格审阅确认：

- 站名“F# 思维 / Thinking in F#”；
- VitePress 作为站点生成器；
- F# 10 / .NET 10 LTS 作为首版基线；
- 活动预约系统作为贯穿项目；
- 七部分、45 章的内容边界。
