# 前言：如何使用本书 {#overview}

本书帮助你从表达式、类型、函数与数据变换出发，用 F# 的方式推理。随后，这些思想会进入副作用、.NET 边界、测试、架构和生态选择，让既有语言经验成为背景，而非逐句套用的模板。

## 本书适合谁，以及覆盖什么 {#audience}

如果你刚开始学习 F#，本书就适合你。具备一点编程经验会有帮助，但前几章会先解释每个 F# 概念，再在后文使用它。你可能希望：

- 把函数式编程学成一种实用的软件组织方式；
- 从 C# 或另一门 .NET 语言转向 F#，并保留已有的平台知识；
- 显式建模领域规则、失败、副作用与并发；
- 现实地判断 F# 在 Web、数据、云、桌面、自动化或 Unity 中的位置；
- 从脚本逐步走向经过测试且可诊断的应用。

本书提供一条带可运行证据与决策标准的学习路径。需要穷尽语法、包目录、框架配方或易变平台契约时，请继续阅读正文链接的官方参考。

## “用 F# 思考”是什么意思 {#fsharp-first}

“用 F# 思考”意味着从值、类型和显式边界开始推理。本书会反复追问：

1. 这个表达式产生什么值？
2. 推断类型或公开类型允许什么？
3. 数据模型显式列出了哪些情况？
4. 哪段变换是纯的，副作用由哪条边界拥有？
5. 哪项可观察证据能区分正确设计和看似可信的错误设计？

这种视角会为对象、可变性、异常、任务和 .NET API 安排有意选择的边界。这里的“掌握”意味着既理解语法，也能用可观察证据解释边界与取舍。

## 沿一条清楚路线学习 {#reading-routes}

把[目录](../)当作地图。第一至第三部分请按顺序阅读，它们依次建立表达式与函数、类型建模、组合与程序结构。然后用第四部分学习副作用与并发，用第五部分理解 .NET 工程，再在第六部分完成一条完整工作流。掌握语言基础后，可按兴趣选读第七部分。

把预测当作学习进度信号：熟悉的语法可以快速通过；预测与编译器或实际输出出现差异时，就在该章深入理解原因。

## 把每章用作反馈循环 {#chapter-loop}

学习每章时：

1. 阅读本章成果，并检查重要类型签名；
2. 运行前先预测输出、失败、顺序或所有权；
3. 复制并运行范围最小的相关代码块；
4. 用自己的话解释结果；
5. 完成全部三道练习后再打开答案；
6. 比较契约与证据，然后修订自己的答案。

封闭题可能只有很窄的可观察结果，诊断题和设计题则可能有多个可靠答案。[答案与评审指南](../appendices/g-solutions-guide)解释评分维度并链接全部答案；把书中解答用作反馈，再从契约与证据出发论证自己的答案。

## 只运行当前需要的范围 {#running-examples}

你可以直接在浏览器阅读本站。要运行示例，请安装[附录 A](../appendices/a-setup)所述 SDK，然后在终端确认：

```console
dotnet --version
```

把章节代码块复制到 `lesson.fsx` 等文件中，然后直接运行：

```console
dotnet fsi --exec lesson.fsx
```

有些示例会故意触发编译错误；正文会把它们标成预期失败，并提前说明应观察的诊断。生态章节若只做资料审阅、方案建议或人工平台检查，也会明确说明。

## 先读类型，再读实现 {#reading-signatures}

先看最外层形状，从左向右阅读箭头，同时记住 `->` 向右结合。

| 签名 | 阅读方式 |
|---|---|
| `string -> int` | 输入一个字符串，输出一个整数 |
| `int -> int -> int` | 输入一个整数，再输入一个整数，最后输出整数；它可以被部分应用 |
| `(int * int) -> int` | 输入一个包含两个整数的元组，再输出一个整数 |
| `'T list -> 'T option` | 输入元素类型相同的列表；输出同类型的一个元素，或没有值 |
| `Request -> Result<Reservation, BookingError>` | 输入请求；输出预约成功值，或预期的预约错误 |
| `unit -> Task<'T>` | 输入显式启动信号；输出一个异步产生 `'T` 的 .NET 任务 |

例如，把 `values: 'T list -> 'T option` 读作：参数名为 `values`；列表中所有元素共享某个类型 `'T`；成功时返回同一类型；缺失被显式表示。名称有帮助，但类型才是编译器能检查的契约。

签名显得密集时，给每个输入和中间结果命名，不要猜标点。[附录 B](../appendices/b-syntax-reference)是紧凑速查；[术语表](../glossary)定义本版使用的词汇。

## 理解版本与证据边界 {#version-scope}

示例以 F# 10 和 .NET 10 复核。部署软件时应使用仍受支持且打过当前补丁的 SDK 与运行时，并在升级后重新检查行为。涉及特定平台的章节会明确说明证据边界。

F# 10 定义了语言范围。本书优先教授耐久基础，并在版本行为改变真实决策时引入对应特性。包、浏览器、云、移动与 Unity 事实都带复核日期，因为它们的契约比语言核心变化更快。

## 遇到阻塞时 {#recovery}

- 工具缺失或 SDK 选择错误时，查[附录 A](../appendices/a-setup)。
- 标点或优先级阻碍阅读时，查[附录 B](../appendices/b-syntax-reference)。
- 编译器报告陌生 `FS` 编号时，查[附录 E](../appendices/e-compiler-errors)，先修第一条相关错误。
- 术语含义不清时，查[术语表](../glossary)。
- 在库代码中遇到高级特性时，用[附录 H](../appendices/h-advanced-index)决定深入学习、包装还是推迟。

然后从[第 1 章](../part-01/ch-01-first-session)开始。把预测保留下来：预测与编译器证据之间的落差，正是本书最能帮助你学习的地方。
