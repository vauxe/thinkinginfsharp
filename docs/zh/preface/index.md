# 前言：如何使用本书 {#overview}

本书从表达式、类型、函数和数据转换讲起，帮助你理解 F# 如何组织程序。后面再把这些基础用于副作用、.NET 互操作、测试和应用设计。你可以借用其他语言的经验，但不需要把原来的写法逐句翻译成 F#。

## 本书适合谁，以及覆盖什么 {#audience}

如果你刚开始学习 F#，本书就适合你。具备一点编程经验会有帮助，但前几章会先解释每个 F# 概念，再在后文使用它。你可能希望：

- 把函数式编程学成一种实用的软件组织方式；
- 从 C# 或另一门 .NET 语言转向 F#，并保留已有的平台知识；
- 显式建模领域规则、失败、副作用与并发；
- 现实地判断 F# 在 Web、数据、云、桌面、自动化或 Unity 中的位置；
- 从脚本逐步走向经过测试且可诊断的应用。

本书用示例和练习组织学习路线，但不是完整的语言规范或框架手册。需要查询所有语法、包版本或平台细节时，请使用正文链接的官方资料。

## “用 F# 思考”是什么意思 {#fsharp-first}

“用 F# 思考”意味着先看值和类型，再判断每项职责应该放在哪里。本书会反复追问：

1. 这个表达式产生什么值？
2. 推断类型或公开类型允许什么？
3. 数据模型明确列出了哪些情况？
4. 哪段变换是纯的，每种副作用在哪一层执行？
5. 哪个可观察结果能区分正确设计和看似可信的错误设计？

这样做的目的，是让对象、可变状态、异常、异步任务和 .NET API 只出现在真正需要它们的位置。掌握之后，你不仅能读懂语法，也能解释一段代码负责什么、为什么放在这里，以及如何验证它。

## 沿一条清楚路线学习 {#reading-routes}

把[目录](../)当作学习地图：

- 第 1–18 章按顺序阅读，建立 F# 语言、类型建模和程序结构基础；
- 第 19–32 章把这些基础用于 I/O、异步、并发、.NET 互操作、测试和应用组织；
- 第 33–38 章用预约系统解释多层设计。它们是相互关联的页面示例，不要求你组装完整项目；
- 第 39–44 章介绍 Web、数据、浏览器、云、UI 和 Unity，可按兴趣选读；
- 第 45 章讲脚本、包和后续练习路线。

用预测检验自己是否理解。熟悉的语法可以快速通过；编译器或程序结果与预测不同时，就在该章深入理解原因。

## 把每章用作反馈循环 {#chapter-loop}

学习每章时：

1. 找出开篇提出的问题，并检查重要类型签名；
2. 运行前先预测输出、失败、顺序或资源归属；
3. 先预测最小相关代码块的结果；需要执行时，再运行该代码块或正文指定的样例；
4. 用自己的话解释结果；
5. 完成全部三道练习后再打开答案；
6. 对照题目约束与实际结果，然后修订自己的答案。

有些练习有唯一结果，诊断题和设计题则可能有多种合理答案。[答案与评审指南](../appendices/g-solutions-guide)说明如何判断答案。先独立作答，再把书中答案当作反馈；如果你的方案不同，只要满足题目约束并有验证依据，也可以成立。

## 只运行需要的示例 {#running-examples}

你可以直接在浏览器阅读本站。要运行示例，请安装[附录 A](../appendices/a-setup)所述 SDK，然后在终端确认：

```console
dotnet --version
```

标明为完整、自包含示例的代码块，可以复制到本地文件后直接运行：

```console
dotnet fsi --exec lesson.fsx
```

有些代码块只是同一文件的节选，会使用前面定义的类型或辅助函数。遇到这种情况，请先阅读代码块前的“文件边界”或“上下文”说明，不要把片段当成独立程序。只有单段代码不足以验证时，仓库才保留完整样例；CI 会构建或执行这些已登记样例。生态章节如果只提供页面模板或选型说明，也会明确标出。

以 `examples/` 开头的路径应从仓库根目录运行。以 `path/to/` 开头的路径（如 `path/to/YourSolution.slnx`）只是命令模板；只有你主动实现对应项目时，才需要换成真实路径。学习本书并不要求把所有页面片段组装成完整应用。

## 先读类型，再读实现 {#reading-signatures}

先看最外层结构，从左向右阅读箭头，同时记住 `->` 向右结合。

| 签名 | 阅读方式 |
|---|---|
| `string -> int` | 输入一个字符串，输出一个整数 |
| `int -> int -> int` | 输入一个整数，再输入一个整数，最后输出整数；它可以被部分应用 |
| `(int * int) -> int` | 输入一个包含两个整数的元组，再输出一个整数 |
| `'T list -> 'T option` | 输入元素类型相同的列表；输出同类型的一个元素，或没有值 |
| `Request -> Result<Reservation, BookingError>` | 输入请求；输出预约成功值，或预期的预约错误 |
| `unit -> Task<'T>` | 调用时不传入业务数据；返回一个异步产生 `'T` 的 .NET 任务 |

例如，把 `values: 'T list -> 'T option` 读作：参数名为 `values`；列表中所有元素共享某个类型 `'T`；成功时返回同一类型；没有值时返回 `None`。名称有帮助，但编译器实际检查的是类型。

签名显得密集时，给每个输入和中间结果命名，不要猜标点。[附录 B](../appendices/b-syntax-reference)是紧凑速查；[术语表](../glossary)定义本版使用的词汇。

## 理解版本与验证范围 {#version-scope}

示例以 F# 10 和 .NET 10 复核。真正部署软件时，请使用仍受支持的补丁版 SDK 和运行时，并在升级后重新检查。涉及具体平台的章节会明确区分“页面设计”“本地已验证”和“仍需在目标平台验证”。

F# 10 定义了语言范围。本书优先教授长期稳定的基础，只在版本差异会影响实际决策时引入对应特性。包、浏览器、云、移动与 Unity 信息都带复核日期，因为它们比语言核心变化更快。

## 遇到问题时 {#recovery}

- 工具缺失或 SDK 选择错误时，查[附录 A](../appendices/a-setup)。
- 标点或优先级阻碍阅读时，查[附录 B](../appendices/b-syntax-reference)。
- 编译器报告陌生 `FS` 编号时，查[附录 E](../appendices/e-compiler-errors)，先修第一条相关错误。
- 术语含义不清时，查[术语表](../glossary)。
- 在库代码中遇到高级特性时，用[附录 H](../appendices/h-advanced-index)决定深入学习、包装还是推迟。

然后从[第 1 章](../part-01/ch-01-first-session)开始。记下自己的预测：预测与编译器结果之间的落差，正是本书最能帮助你学习的地方。
