# 第 40 章：数据、类型提供器、分析与机器学习 {#overview}

F# 的记录、度量单位、模式匹配、序列与高阶函数能直接描述形状和流动，因此数据转换写起来很自然。这种优势不会替你选择数据库库，不会让外部模式自动可信，不会把查询自动移到服务器，也不会让数据集自动装进内存，更不能证明模型有用。

正确的问题不是“F# 数据栈是什么？”而是“谁拥有这份数据和模式、每项操作必须在哪里执行、工作负载有多大且多敏感，以及探索结束后必须保留什么证据？”本章从一个已验证的小型本地 CSV 切片出发，再谨慎扩展到关系访问、分析、可视化与机器学习。

## 你将能够做到 {#outcomes}

学完本章后，你应当能够：

- 区分编译期样本推断与运行期数据验证；
- 使用类型提供器而不导出其生成的行类型；
- 判断 `Seq` 或查询表达式是在本地执行，还是通过 `IQueryable` 提供器执行；
- 根据所有权与查询形状，在直接 ADO.NET、Dapper、EF Core 和 SQLProvider 之间选择；
- 把数据库 DTO、生成类型和框架实体限制在适配器边界；
- 根据规模和对齐需求选择数组、序列、数据帧或存储侧计算；
- 把探索脚本转化为锁定、测试且可重复的产物；
- 把可视化视为经过审阅的输出边界，而不是“看图即证明”；
- 分离训练、评估、模型打包与在线推理；
- 不受语言阵营影响地比较 ML.NET、ONNX Runtime、TorchSharp 与外部 ML 栈；
- 准确阅读稳定版本、预发布版、目标资产、原生依赖与弃用状态；
- 在生产部署前设计模式漂移与模型漂移证据。

## 从数据契约开始 {#data-contract}

选择库之前，先写清这些事实：

| 问题 | 它为何改变设计 |
|---|---|
| 谁拥有模式？ | 自己的迁移、合作方 API 与用户上传文件具有不同的变更契约 |
| 形状是封闭还是开放？ | 固定表可以映射到记录；稀疏或演进的特征可能需要动态表示 |
| 数据可能增长到多大？ | 六行、六百万行与无界流需要不同的求值模型 |
| 筛选与聚合必须在哪里运行？ | 筛选前传输整张表即使结果相同，也可能在运维上错误 |
| 是否涉及写入？ | 事务、并发、重试与幂等比查询语法更重要 |
| 什么会缺失、无效或迟到？ | 缺席、损坏与尚未到达是不同的领域状态 |
| 什么是敏感信息？ | 样本、日志、图表、缓存、模型文件与 notebook 输出都可能泄露数据 |
| 什么必须可复现？ | 一次性探索与受监管的训练运行需要不同的来源证据 |

回答这些问题后再选择表示：

| 工作负载 | 有用的首选表示 | 何时重新考虑 |
|---|---|---|
| 小型、有界转换 | 记录加 `Array`、`List` 或 `Seq` | 标签、对齐或缺失数据操作占据主体 |
| 关系型应用状态 | 数据库适配器之上的显式仓储/端口 | 分析查询开始对抗事务模型 |
| 带标签的异构分析 | 数据帧或序列 | 内存、类型或部署约束占据主体 |
| 大型分析扫描 | 存储引擎、列式格式或数据仓库查询 | 本地迭代成为瓶颈 |
| 随时间到达的事件 | `IAsyncEnumerable`、通道或流系统 | 批次快照才是真实业务单位 |
| 模型训练 | 版本化表格/张量管道 | 生产推理只需要一个小型导出模型 |

没有任何行处理库能免除领域含义建模。数据库 `NULL`、空 CSV 单元格、缺失 JSON 属性、`NaN` 与“尚未测量”不应偶然坍缩成同一个值。

## 检查已验证的本地 CSV 切片 {#representative-sample}

数据样例以 `net10.0` 为目标，并锁定 [FSharp.Data 8.2.0](https://www.nuget.org/packages/FSharp.Data/8.2.0)。其包锁文件记录解析后的完整传递图。唯一编译期数据源是 `sample.csv`；编译不依赖 URL、数据库、账号或机密。

官方 [CSV 提供器指南](https://fsprojects.github.io/FSharp.Data/library/CsvProvider.html) 解释了两个不同时刻：检查代码时由样本提供列名和推断类型，运行时则由 `Load` 或 `Parse` 提供数据。数据样例让设计期位置不受构建工作目录影响：

```fsharp:line-numbers [Program.fs]
type private Orders =
    CsvProvider<
        "../../../sample.csv",
        ResolutionFolder=ResolutionFolder,
        Culture="en-US",
        PreferDateOnly=true
     >
```
固定样本使 `Units` 成为 `int`、`UnitPrice` 成为 `decimal`、`OrderedAt` 成为 `DateOnly`。`Culture="en-US"` 与 `PreferDateOnly=true` 都是推断契约的一部分。改变这些静态参数或样本，生成的 API 就可能在编译期变化。

这是有用反馈，但不是运行期证明。后续文件仍可能缺失、不可读、过大、编码不同、格式错误或语义无效。样本是模式见证，不是未来每个字节的验证器。

### 把生成行留在适配器内 {#generated-row-boundary}

数据样例不返回 `Orders.Row`，而是把生成行转换成普通记录：

```fsharp:line-numbers [Program.fs]
type RegionSummary =
    { Region: string
      OrderCount: int
      Units: int
      Revenue: decimal }

type HighValueOrder =
    { OrderId: string
      Region: string
      OrderedAt: DateOnly
      Revenue: decimal }
```
这个边界有三个好处：

- 调用方不会继承提供器包或由样本派生的公开 API；
- 领域名称与必填字段可以不同于源列名；
- 以后改用数据库、另一解析器或显式模式时，只需改变适配器，而不是所有消费者。

这里的记录是分析输出，不是预约领域实体。真实摄取边界还应验证标识符、范围、货币、时区、重复项与业务含义，然后才能构造可信领域值。

### 普通序列组合够用时就使用它 {#sequence-aggregation}

区域汇总对生成行分组，每组只物化一次，计算总数、排序并返回列表：

```fsharp:line-numbers [Program.fs]
let summarizeByRegion (path: string) : RegionSummary list =
    Orders.Load(path).Rows
    |> Seq.groupBy _.Region
    |> Seq.map (fun (region, rows) ->
        let rows = Seq.toArray rows

        ({ Region = region
           OrderCount = rows.Length
           Units = rows |> Array.sumBy _.Units
           Revenue = rows |> Array.sumBy revenue }
        : RegionSummary))
    |> Seq.sortByDescending _.Revenue
    |> Seq.toList
```
数据集只有六行，因此内存内序列是诚实选择。管道之所以易读，是因为求值预算已知。把相同代码盲目用于 60 GB 文件会改变运维契约：`CsvProvider` 默认缓存行；即使关闭缓存，`groupBy`、排序和最终物化仍可能保留大量数据。

### 根据来源理解查询表达式 {#query-expression-sample}

第二个函数使用 F# 查询语法：

```fsharp:line-numbers [Program.fs]
let highValueOrders (minimumRevenue: decimal) (path: string) : HighValueOrder list =
    query {
        for row in Orders.Load(path).Rows do
            let rowRevenue = revenue row
            where (rowRevenue >= minimumRevenue)
            sortByDescending rowRevenue

            select (
                { OrderId = row.OrderId
                  Region = row.Region
                  OrderedAt = row.OrderedAt
                  Revenue = rowRevenue }
                : HighValueOrder
            )
    }
    |> Seq.toList
```
这里的 `Orders.Load(path).Rows` 是进程内序列，因此筛选、排序与投影都在本地执行。语法像数据库查询，但根本没有 SQL。

聚焦测试精确断言六行数据的聚合、`DateOnly` 值、阈值与降序。锁定还原后，Release `--no-restore` 构建与测试无需网络模式即可通过。控制台把用户提供的路径解析为绝对路径，并打印三条确定汇总。这些证据只覆盖固定本地形状和计算；不覆盖任意上传、巨型文件、编码攻击或数据库提供器。

## 把模式视为版本化依赖 {#schema-dependency}

类型提供器通过根据检查时可用的信息生成 API，把一部分反馈前移。你必须决定这些信息来自哪里。

### 稳定的本地样本 {#stable-samples}

提交到仓库的样本应当：

- 小巧、合成或已安全去标识，并可合法审阅；
- 能代表表头、分隔符、区域性、可选性与边界值；
- 与代码一同版本化，并可供每次干净构建使用；
- 配有兼容和不兼容运行期输入测试；
- 在接受的模式变化时有意修改。

不要仅为获得 IntelliSense 而提交生产导出。样本、生成输出、构建缓存与测试失败消息都会成为信息边界的一部分。

### 实时设计期来源 {#live-design-time-sources}

编译期间检查 URL 或数据库，会把构建耦合到可用性、凭据、网络策略、服务器版本与可变外部状态。一次开发者会话中的成功构建，可能在 CI 失败，也可能明天悄悄暴露不同的生成表面。

如果数据库类型提供器确实有价值，应尽可能使用它支持的离线模式机制。否则使用最小权限的仅模式账号，把机密留在静态参数与源码之外，锁定驱动/提供器图，并把必要设计期服务声明为显式构建依赖。缓存失效策略不是模式治理。

### 动态或合作方控制的数据 {#dynamic-data}

对于真正开放的数据，代表性样本仍可改善易用性，但解析后要放置显式解码层：

```text
字节 -> 语法解析器 -> 源形状值 -> 验证 -> 可信模型
```

决定新字段是忽略还是拒绝、缺失字段是可选还是错误、数值拓宽如何工作，以及多个版本如何共存。在策略允许时，保留原始输入或安全摘要用于诊断。类型推断无法替你决定这些兼容规则。

## 知道查询在哪里执行 {#query-execution}

[F# 查询表达式参考](https://learn.microsoft.com/en-us/dotnet/fsharp/language-reference/query-expressions) 支持 LINQ 风格查询，但来源控制其含义。

| 来源 | 典型执行位置 | 重要后果 |
|---|---|---|
| `list`、数组、`seq`、CSV 行 | 本地 .NET 枚举 | 可以使用 F# 函数，但 CPU 与数据移动由你承担 |
| 来自 EF 或其他提供器的 `IQueryable<'T>` | 由提供器翻译表达式树 | 只有受支持的表达式可翻译；适用 SQL/提供器语义 |
| 物化结果后接 `Seq` | 先远程，后本地 | 精确物化点设定数据传输边界 |
| 异步流 | 增量本地副作用 | 取消、释放、背压与部分失败都很重要 |

因此相同外观的 `where` 可能表示本地谓词，也可能表示提供器表达式。不受支持的翻译会抛错；不同提供器版本可能给出不同翻译；数据库的空值、排序规则、小数、日期与排序语义也可能不同于 .NET。

在命名与测试中让边界可见。对重要查询检查生成 SQL 或提供器诊断。只投影必需列，限制结果大小，传递取消；方言或事务行为重要时，要针对真实数据库引擎测试。内存提供器不是生产 SQL 的证据。

如果枚举会执行 I/O，就不要把远程查询藏在无辜的 `seq<'T>` 后面。`search : Query -> CancellationToken -> Task<SearchResult list>` 这样的端口能更诚实地说明副作用、物化与取消边界。

## 根据控制权与变更所有权选择关系访问 {#relational-access}

F# 可以使用完整的 .NET 数据库生态。有用的区分不是“F# 库还是 C# 库”，而是每种选择拥有多少 SQL、映射、跟踪、模式发现与生命周期责任。

### 直接 ADO.NET 提供器 {#ado-net}

当精确 SQL、流式处理、批量操作、提供器特性或最小依赖很重要时，使用供应商 `DbConnection`、参数化 `DbCommand` 与读取器。映射、空值处理、事务、释放、重试和诊断由你负责。这通常是优秀的窄适配器，不是关于“手写管道更高尚”的竞赛。

绝不要用插值把不受信值拼进 SQL。参数能保护值；动态标识符和查询结构需要允许列表或查询构建器。尽可能晚地打开连接，确定性释放读取器与命令，并向异步操作传递取消。

### Dapper {#dapper}

[Dapper 2.1.79](https://www.nuget.org/packages/Dapper/2.1.79) 是 ADO.NET 之上的 SQL 优先对象映射器。它能减少重复参数和行映射，同时保持查询文本与事务所有权可见。

它适合读模型，以及希望显式掌控 SQL 的服务团队。F# 摩擦会出现在构造函数、匿名参数、选项、记录与空值处；用 CLR 友好的持久化 DTO 和小型映射函数限制这些摩擦。Dapper 不会替你设计聚合、迁移、并发规则或安全 SQL 组合。

### Entity Framework Core {#ef-core}

EF Core 拥有更广的工作单元、变更跟踪、关系、LINQ 翻译、迁移与提供器模型。[EF Core 10](https://learn.microsoft.com/en-us/ef/core/what-is-new/ef-core-10.0/whatsnew) 是 .NET 10 LTS 产品线，并要求 .NET 10 运行时。

只有该应用模型及其提供器生态能够回报约定成本时才选择它。F# 可以调用 EF Core，但可变实体形状、导航属性、表达式翻译、特性、代理假设与 C# 优先示例，可能让持久化实体不适合充当领域类型。把 EF 实体留在基础设施中并映射到不可变记录/联合，不要为了跟踪便利而削弱领域。

### SQLProvider {#sqlprovider}

[SQLProvider 1.5.27](https://www.nuget.org/packages/SQLProvider/1.5.27) 是 F# 数据库类型提供器，具有 LINQ 查询、模式探索、CRUD、多种数据库后端与离线模式选项。当数据库模式稳定且提供器支持与目标匹配时，它能给出优秀反馈。

采用试验（spike，即为验证关键风险而构建、便于删除的小型实现）必须涵盖真实驱动、设计期模式路径、生成 SQL、可空性、事务、异步/取消、迁移、发布输出与 CI 还原。生成实体仍是适配器类型。47 MB 包下载及其驱动/原生图是需要检查的运维事实，而不是质量评判。

### 比较所有权表面 {#relational-comparison}

| 需求 | 首选候选 | 必须提供的主要证据 |
|---|---|---|
| 精确 SQL 与提供器特性 | 直接 ADO.NET | 映射、生命周期、取消、事务与注入测试 |
| 显式 SQL 且减少映射样板 | Dapper | F# DTO 映射、参数化、多重映射与事务行为 |
| 变更跟踪与丰富应用模型 | EF Core | 真实提供器翻译、并发、迁移与实体/领域分离 |
| 编译期数据库形状的 F# 访问 | SQLProvider | 可重复模式获取、生成 SQL、驱动与部署兼容性 |

同一服务可以使用写入导向适配器与独立读取投影。没有精确边界时，不要让两个库拥有同一事务或迁移路径。

## 分离事务与领域决策 {#transactions-domain}

数据库库暴露机制；应用拥有含义。把唯一性、容量、版本检查或账本余额放进真正保护它们的原子边界。把唯一约束违反与乐观并发冲突映射为已声明的应用结果，而不是泄漏供应商异常。

重试需要幂等与事务知识。重试只读瞬态失败，不同于提交期间连接中断后重试命令。用有界标签测量连接池饱和、查询耗时、返回行数、重试与冲突；默认不要记录完整 SQL 参数或行内容。

对于迁移，要分开“应用可读取两种形状”“模式已改变”“旧写入方已停止”与“旧列已删除”。重新编译类型提供器和生成一份 ORM 迁移文件，都不能证明滚动部署兼容。

## 根据操作与规模选择分析结构 {#analytical-structures}

当行数有界且操作类型稳定时，从普通 F# 集合开始。数组提供紧凑索引存储；序列支持延迟管道；列表很适合递归构造，但通常不是密集数值表的最佳选择。

[Deedle 8.0.0](https://www.nuget.org/packages/Deedle/8.0.0) 以 `net10.0` 为目标，提供带标签序列与数据帧、对齐、连接、缺失数据操作、分组、统计和时间序列函数。当这些语义真正减少工作时选择它，而不是让每个 CSV 都变成数据帧。

数据帧以部分静态行形状可见性换取异构列和交互式操作。要显式指定键、重复处理、对齐、缺失值、顺序与转换。一个打印漂亮的数据帧仍可能含有 `object` 列、静默强制转换或错位时间序列。

当数据超出预期内存预算时，把投影和聚合下推到数据库或分析引擎、对工作负载分区，或使用合适的列式格式。用代表性基数基准测试解析、分配、连接与序列化。“惰性”不代表分组、排序、缓存或物化后仍是常量内存。

## 让探索可复现 {#reproducible-exploration}

SDK 自带 [F# Interactive](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/)：`dotnet fsi` 可运行 REPL 或版本化 `.fsx` 脚本。它是很好的草稿表面，因为语言与运行时相同，但交互式会话仍携带隐藏状态。

为了得到持久结果，应记录：

- 精确 SDK 和包版本及锁定信息；
- 不可变输入标识、模式版本与允许的获取步骤；
- 区域性、时区、文本编码与缺失值策略；
- 随机种子与确定性限制；
- 单元格或步骤执行顺序；
- 预期表格、指标或产物哈希；
- 从干净进程复现结果的无界面命令。

把可复用解析、特征和计算迁移到带测试的编译模块。脚本中只保留编排与呈现。如果分析改变产品决定，就像审阅应用代码一样审阅它。

旧资料经常推荐 Polyglot Notebooks 或 .NET Interactive。Microsoft 已于 [2026-03-27 弃用 Polyglot Notebooks，并于 2026-04-24 弃用 .NET Interactive](https://github.com/dotnet/interactive/issues/4163)；其仓库已经归档。现有安装可能暂时继续工作，但不再获得新功能或弃用后的安全修复。不要把它们作为新项目默认值。如果 notebook 呈现不可或缺，应单独评估当前仍维护的 Jupyter 内核。

## 把可视化视为输出边界 {#visualization}

[Plotly.NET 5.1.0](https://www.nuget.org/packages/Plotly.NET/5.1.0) 是已核对的稳定包；核对日的 6.0 包仍是预发布版。它从 .NET 构建 plotly.js 图表描述，并有相关交互与图像导出包。

图表选择不只包括构造函数：

- 交互 HTML，还是确定的静态图像或矢量导出；
- 浏览器/CDN 策略、离线资源、内容安全策略与包大小；
- 颜色、标签、单位、时区、聚合与不确定性；
- 可访问标题、文字摘要、表格替代、对比度与键盘行为；
- 工具提示、嵌入数据、文件名或导出元数据是否暴露敏感行；
- 服务器、桌面、notebook 或浏览器渲染及其原生/运行时依赖。

先测试图表的数据表，再测试像素。把选择分箱、分母、平滑和缺失值的转换与渲染分离。一个视觉可信的图表可以用完美排版编码错误总体。

## 选择机器学习边界，而不仅是训练器 {#machine-learning}

首先决定任务与产品决策。分类、回归、排序、推荐、异常检测、预测、向量相似度检索与生成具有不同标签、指标、延迟和失败成本。对于已有数据，规则基线可能更便宜、更可解释，也更准确。

诚实的训练工作流包括：

```text
版本化观察
  -> 防泄漏切分
  -> 拟合预处理与特征
  -> 基线与候选训练
  -> 适合任务的评估
  -> 不可变模型加模式/元数据
  -> 部署验证
  -> 受监控推理与再训练决定
```

在拟合会从数据学习的转换之前先切分。当随机按行切分会把未来或同一客户泄漏到不同集合时，要保留实体或时间边界。报告与产品成本相关的指标、不确定性与基线；没有数据切片和阈值的“准确率提高”并不完整。

### ML.NET {#mlnet}

[ML.NET](https://learn.microsoft.com/en-us/dotnet/machine-learning/mldotnet-api) 提供 .NET 数据视图、转换、训练器、评估、模型持久化，以及 ONNX 和 TensorFlow 等导入路径。[Microsoft.ML 5.0.0](https://www.nuget.org/packages/Microsoft.ML/5.0.0) 是已核对的稳定包；核对日的 6.0 仍是预发布版。

对于必须在 .NET 环境内训练或推理的经典 ML，它是强候选。F# 可以使用 CLR API，但特性、可变输入/输出类、泛型重载与示例都偏 C# 形状。把这些形状放进 ML 适配器，再从已验证的 F# 特征记录映射。通过在新进程中加载持久模型来测试它，而不只用刚训练出的内存对象预测。

### ONNX Runtime {#onnx-runtime}

当训练发生在别处、产品需要可移植推理时，[ONNX Runtime 的 .NET 绑定](https://onnxruntime.ai/docs/get-started/with-csharp.html) 是候选。边界是模型具名张量、数据类型、维度、预处理、输出解释与执行提供器，而不是一次 `Run` 调用。

锁定模型摘要和运行时/原生包，推理前验证张量形状，按文档所有权复用会话与缓冲区，限制并发，并在每种目标架构测试。ONNX 文件是可执行供应链输入，应像代码一样审阅与分发。

### TorchSharp 或外部训练栈 {#torchsharp-external}

[TorchSharp 0.107.0](https://www.nuget.org/packages/TorchSharp/0.107.0) 向 .NET 暴露 LibTorch 引擎。当张量和深度学习工作必须留在 .NET 时，它很有用，但原生 CPU/GPU 包、架构支持、张量释放、设备放置、可复现性与 1.0 前 API 生命周期都会进入运维契约。

如果外部 Python 或托管训练平台的算法、硬件工具、实验跟踪或团队经验明显占优，就选择它。通过版本化文件、ONNX、批任务、队列或服务契约保持边界显式。跨进程往往比为整个快速演进生态维护私有 F# 包装器更简单。

### 分离训练与服务 {#training-serving}

| 关注点 | 训练 | 在线推理 |
|---|---|---|
| 主要目标 | 学习与比较 | 在延迟/错误预算下稳定决策 |
| 数据 | 带标签的版本化历史集合 | 一个请求或含已验证特征的有界批次 |
| 生命周期 | 迭代、资源密集，通常离线 | 长生命周期模型/会话与受控并发 |
| 证据 | 切分、基线、指标、种子、来源 | 启动加载、模式兼容、负载、失败、回滚 |
| 监控 | 实验与数据质量 | 延迟、错误、特征/模型漂移、决策结果 |

不要在 Web 启动期间训练，也不要为每个请求构造预测引擎，除非测量和所有权明确证明合理。预热模型，定义线程安全，在诊断中显示版本，并保留上一份不可变产物用于回滚。

## 开展范围受限的数据栈试验 {#adoption-spike}

对每个候选使用一条代表路径和相同验收数据：

- 一个含空值、Unicode、时间、小数与边界值的真实模式；
- 一条含投影、筛选、排序和有界结果的成功查询；
- 一个带已声明错误的格式错误或不兼容输入；
- 一次取消与一次依赖/瞬态失败；
- 如果存在写入，则包含一次写冲突或事务边界；
- 代表规模下的生成 SQL、分配、行数与延迟证据；
- 锁定还原、干净 Release 构建、发布、启动与目标平台执行；
- 审阅机密、日志、临时文件、可视化输出与模型产物；
- 一次升级或模式演进练习，以及失败试验的删除条件。

先比较正确性与所有权，再比较语法。一个假设实时开发数据库、下载模式、加载全部行或隐藏原生运行时的十行演示并不更小；它只是把工作移出了文件。

## 避免常见数据错误 {#common-mistakes}

- 把样本推断类型当成所有运行期文档的验证。
- 在未声明构建依赖时，针对可变 URL 或生产数据库编译。
- 把机密或敏感生产行放入静态参数、样本、notebook 或图表。
- 从应用核心返回生成行、ORM 实体或张量对象。
- 不检查来源与物化点，就假设 `query {}` 表示 SQL。
- 因过早调用 `Seq.toList`，在本地运行本可翻译的表达式。
- 把内存数据库测试当成生产翻译或事务行为的证明。
- 把值插值进 SQL，或默认记录参数内容。
- 因 API 返回 `seq` 或自称惰性，就加载无界数据集。
- 当小型类型化数组更清晰安全时仍使用数据帧。
- 只因版本号更大就选择预发布版，而不是稳定产品线。
- 从旧教程开始使用已弃用 notebook 工具建立新工作流。
- 把图表当成验证，或把单一模型指标当成产品决定。
- 在训练/测试切分前拟合预处理，从而泄漏评估数据。
- 在 ML 部署中忽略原生包、模型来源、会话生命周期或回滚。

## 练习 {#exercises}

### 练习 1：选择三个数据边界 {#exercise-01}

为每种情况选择并论证首选候选：（a）F# 预约服务需要事务写入、乐观并发和五条精心调优的 PostgreSQL 查询；（b）分析师按日期连接三个有界 CSV 导出、探索缺失值，并每周发布一张可访问图表；（c）Web API 接收版本化特征 DTO，必须在 30 ms 内运行由 Python 团队训练的模型，且不能有网络跳转。每种情况至少比较两个选择，并列出反转证据。

### 练习 2：为 CSV 模式漂移设计 {#exercise-02}

供应商把 `UnitPrice` 改成 `Price`，加入 `Currency`，有时发送空白 `OrderedAt`，还可能追加未知列。围绕数据样例设计 v1/v2 摄取边界。指定编译期样本、语法解析、源 DTO、兼容规则、领域验证、隔离证据、夹具用例与删除 v1 支持的条件。不要通过把所有小数视为可互换来解决货币问题。

### 练习 3：把探索模型生产化 {#exercise-03}

一个 `.fsx` 脚本加载本地导出、构造特征、训练分类器、打印准确率并绘图。设计把它转化为可重复训练任务和可独立部署推理组件的路径。包含不可变数据标识、防泄漏切分、基线与分片指标、包/模型锁、特征模式、机密处理、无界面测试、模型注册元数据、启动/负载证据、监控与回滚。

## 本章回顾 {#chapter-review}

- 从模式所有权、执行位置、规模、副作用、敏感度与证据开始。
- 类型提供器把样本转成编译期反馈；它不会验证所有运行期数据。
- 把生成行与数据库实体留在适配器内，再返回普通可信类型。
- `Seq` 与 `query {}` 描述语法；来源决定本地枚举还是提供器翻译。
- ADO.NET、Dapper、EF Core 与 SQLProvider 各自拥有不同程度的 SQL、映射、跟踪与模式发现。
- 只有应用把完整决策放进真实原子边界时，事务才能保护不变量。
- 有界类型化工作使用普通集合；标签、对齐与缺失数据值得时再用数据帧。
- 在探索成为决策证据前，使其可无界面运行且可重复。
- .NET Interactive 与 Polyglot Notebooks 已弃用；要显式评估仍维护的 notebook 工具。
- 测试图表输入与可访问性；视觉可信不等于正确。
- 分离训练证据、不可变模型打包与推理运维。
- ML.NET 适合许多进程内 .NET 任务；ONNX 是推理契约；TorchSharp 增加原生张量/运行时所有权。
- 版本表是带日期观察；应用必须验证自己采用的选项。
- 选择满足真实工作负载的最小边界，再锁定、测试、测量并演练变化。

第 41 章把相同纪律带进浏览器：Fable 把 F# 编译为 JavaScript，那里的运行时、API 表面、包图与状态模型都不同于服务端 .NET。
