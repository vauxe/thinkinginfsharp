# 第 40 章：数据、类型提供程序、分析与机器学习 {#overview}

F# 的记录、度量单位、模式匹配、序列和高阶函数都很适合表达数据转换。不过，语言只能帮助你写清转换规则。使用哪个库、能否信任输入结构、查询在哪里执行，以及数据能否放进内存，仍要分别判断。

不存在一套适合所有情况的“F# 数据栈”。选择工具前，先确认数据由谁提供、结构是否稳定、处理在哪里执行、数据有多大，以及结果能否重复得到。本章先用小型 CSV 说明这些问题，再介绍数据库、分析、可视化和机器学习的选择边界。

本章是可选的数据应用拓展，不是掌握 F# 核心语法的必修内容。代码只展示文件如何配合，不要求你重建完整项目。当前仓库也不包含原先的 `examples/ecosystem/data` 项目或 CSV 测试数据。

术语分成三类：

- “类型提供程序”和“查询表达式”属于 F# 语言或工具链；
- `CsvProvider`、Deedle、Dapper 和 ML.NET 是具体的库或平台 API；
- “数据帧”“特征”和“模型漂移”来自数据分析与机器学习。

先阅读[数据契约](#data-contract)、[查询在哪里执行](#query-execution)和[事务与业务决策](#transactions-domain)。类型提供程序、可视化和机器学习部分可在实际需要时再查阅。
:::

## 从数据契约开始 {#data-contract}

选择库之前，先写清这些事实：

| 问题 | 它为何改变设计 |
|---|---|
| 谁负责模式？ | 自己的迁移、合作方 API 与用户上传文件具有不同的变更契约 |
| 结构是封闭还是开放？ | 固定表可以映射到记录；稀疏或演进的特征可能需要动态表示 |
| 数据可能增长到多大？ | 六行、六百万行与无界流需要不同的求值模型 |
| 筛选与聚合必须在哪里运行？ | 筛选前传输整张表即使结果相同，也可能在运维上错误 |
| 是否涉及写入？ | 事务、并发、重试与幂等比查询语法更重要 |
| 什么会缺失、无效或迟到？ | 缺席、损坏与尚未到达是不同的领域状态 |
| 什么是敏感信息？ | 样本、日志、图表、缓存、模型文件与 notebook 输出都可能泄露数据 |
| 什么必须可复现？ | 一次性探索与受监管训练需要不同的来源记录 |

回答这些问题后再选择表示：

| 工作负载 | 有用的首选表示 | 何时重新考虑 |
|---|---|---|
| 小型、有界转换 | 记录加 `Array`、`List` 或 `Seq` | 标签、对齐或缺失数据操作占据主体 |
| 关系型应用状态 | 数据库适配器之上的仓储或端口 | 分析查询开始与事务模型冲突 |
| 带标签的异构分析 | 数据帧或序列 | 内存、类型或部署约束占据主体 |
| 大型分析扫描 | 存储引擎、列式格式或数据仓库查询 | 本地迭代成为瓶颈 |
| 随时间到达的事件 | `IAsyncEnumerable`、通道或流系统 | 批次快照才是真实业务单位 |
| 模型训练 | 版本化表格/张量管道 | 生产推理只需要一个小型导出模型 |

没有任何行处理库能免除领域含义建模。数据库 `NULL`、空 CSV 单元格、缺失 JSON 属性、`NaN` 与“尚未测量”不应偶然混为同一个值。

## 检查可重建的本地 CSV 模板 {#representative-sample}

如果你选择重建示例，`DataSample.fsproj` 以 `net10.0` 为目标，只编译 `Program.fs`，并固定使用 [FSharp.Data 8.2.0](https://www.nuget.org/packages/FSharp.Data/8.2.0)。首次还原后保留新生成的包锁文件。编译期只读取与 `Program.fs` 同目录的 `sample.csv`，不依赖 URL、数据库、账号或机密。

`Program.fs` 以 `namespace ThinkingInFSharp.Ecosystem.Data` 开头，导入 `System`、`System.Globalization` 和 `FSharp.Data`。两个输出记录位于命名空间级；提供程序类型、`revenue`、两个查询函数位于 `DataSample` 模块；命令行解析与打印位于最后的 `Program` 入口模块。所有代码块都是这一文件的节选，不能分开运行。

为了让推断契约可见，`sample.csv` 可使用以下六行合成数据：

```csv [sample.csv]
OrderId,Region,Product,Units,UnitPrice,OrderedAt
ORD-1001,North,Keyboard,2,75.50,2026-01-02
ORD-1002,South,Monitor,1,240.00,2026-01-03
ORD-1003,North,Mouse,4,25.00,2026-01-04
ORD-1004,West,Dock,3,110.00,2026-01-05
ORD-1005,South,Keyboard,2,80.00,2026-01-06
ORD-1006,West,Cable,5,12.00,2026-01-07
```

官方 [CSV 提供程序指南](https://fsprojects.github.io/FSharp.Data/library/CsvProvider.html) 解释了两个不同时刻：检查代码时由样本提供列名和推断类型，运行时则由 `Load` 或 `Parse` 提供数据。数据样例让设计期位置不受构建工作目录影响：

```fsharp:line-numbers [Program.fs]
[<Literal>]
let private ResolutionFolder = __SOURCE_DIRECTORY__

type private Orders =
    CsvProvider<
        "sample.csv",
        ResolutionFolder=ResolutionFolder,
        Culture="en-US",
        PreferDateOnly=true
     >
```
固定样本使 `Units` 成为 `int`、`UnitPrice` 成为 `decimal`、`OrderedAt` 成为 `DateOnly`。`Culture="en-US"` 与 `PreferDateOnly=true` 都是推断契约的一部分。改变这些静态参数或样本，生成的 API 就可能在编译期变化。

这些编译期反馈只确认固定样本呈现的结构。后续每份输入仍需在运行时检查文件存在性与访问权限、大小、编码、语法和领域含义。

### 把生成行留在适配器内 {#generated-row-boundary}

数据样例不返回 `Orders.Row`，而是把生成行转换成普通记录：

```fsharp:line-numbers [Program.fs]
type RegionSummary =
    { Region: string
      OrderCount: int
      Units: int
      Revenue: decimal }

type HighValueOrder =
    { OrderId: string
      Region: string
      OrderedAt: DateOnly
      Revenue: decimal }
```
这个边界有三个好处：

- 调用方不会继承提供程序包或由样本派生的公开 API；
- 领域名称与必填字段可以不同于源列名；
- 以后改用数据库、另一解析器或显式模式时，只需改变适配器，而不是所有消费者。

这里的记录是分析输出，不是预约领域实体。真实摄取边界还应验证标识符、范围、货币、时区、重复项与业务含义，然后才能构造可信领域值。

### 普通序列组合够用时就使用它 {#sequence-aggregation}

区域汇总对生成行分组，每组只转换一次为数组，计算总数、排序并返回列表：

```fsharp:line-numbers [Program.fs]
let private revenue (row: Orders.Row) = decimal row.Units * row.UnitPrice

let summarizeByRegion (path: string) : RegionSummary list =
    Orders.Load(path).Rows
    |> Seq.groupBy _.Region
    |> Seq.map (fun (region, rows) ->
        let rows = Seq.toArray rows

        ({ Region = region
           OrderCount = rows.Length
           Units = rows |> Array.sumBy _.Units
           Revenue = rows |> Array.sumBy revenue }
        : RegionSummary))
    |> Seq.sortByDescending _.Revenue
    |> Seq.toList
```
数据集只有六行，因此使用内存内序列很合理。管道之所以易读，是因为求值预算已知。把相同代码盲目用于 60 GB 文件会改变运维契约：`CsvProvider` 默认缓存行；即使关闭缓存，`groupBy`、排序和最终保存结果仍可能保留大量数据。

### 根据来源理解查询表达式 {#query-expression-sample}

第二个函数使用 F# 查询语法：

```fsharp:line-numbers [Program.fs]
let highValueOrders (minimumRevenue: decimal) (path: string) : HighValueOrder list =
    query {
        for row in Orders.Load(path).Rows do
            let rowRevenue = revenue row
            where (rowRevenue >= minimumRevenue)
            sortByDescending rowRevenue

            select (
                { OrderId = row.OrderId
                  Region = row.Region
                  OrderedAt = row.OrderedAt
                  Revenue = rowRevenue }
                : HighValueOrder
            )
    }
    |> Seq.toList
```
这里的 `Orders.Load(path).Rows` 是进程内序列，因此筛选、排序与投影都在本地执行。语法像数据库查询，但根本没有 SQL。

如果重建示例，测试应检查六行数据的聚合结果、`DateOnly` 值、筛选阈值和降序排列。还要执行锁定还原，以及 Release 模式的 `--no-restore` 构建和测试。控制台入口把输入路径转成绝对路径，并为固定样本打印三条稳定汇总。即使全部通过，也只能证明这份本地样本和计算正确；它没有覆盖任意上传文件、超大文件、恶意编码或数据库行为。

## 把模式视为版本化依赖 {#schema-dependency}

类型提供程序根据检查时可用的信息生成 API，把一部分反馈前移。你必须决定这些信息来自哪里。

### 稳定的本地样本 {#stable-samples}

提交到仓库的样本应当：

- 小巧、合成或已安全去标识，并可合法审阅；
- 能代表表头、分隔符、区域性、可选性与边界值；
- 与代码一同版本化，并可供每次干净构建使用；
- 配有兼容和不兼容运行期输入测试；
- 在接受的模式变化时有意修改。

不要仅为获得 IntelliSense 而提交生产导出。样本、生成输出、构建缓存与测试失败消息都会成为信息边界的一部分。

### 实时设计期来源 {#live-design-time-sources}

编译期间检查 URL 或数据库，会让构建依赖其可用性、凭据、网络策略、服务器版本与可变外部状态。一次开发者会话中的成功构建，可能在 CI 失败，也可能明天生成不同的 API。

如果数据库类型提供程序确实有价值，应尽可能使用它支持的离线模式机制。否则使用最小权限的仅模式账号，把机密留在静态参数与源码之外，锁定驱动与提供程序依赖图，并把必要的设计期服务列为构建依赖。缓存失效策略不是模式治理。

### 动态或合作方控制的数据 {#dynamic-data}

对于真正开放的数据，代表性样本仍可改善易用性，但解析后要放置显式解码层：

```text
字节 -> 语法解析器 -> 源格式值 -> 验证 -> 可信模型
```

决定新字段是忽略还是拒绝、缺失字段是可选还是错误、数值拓宽如何工作，以及多个版本如何共存。在策略允许时，保留原始输入或安全摘要用于诊断。类型推断无法替你决定这些兼容规则。

## 知道查询在哪里执行 {#query-execution}

[F# 查询表达式参考](https://learn.microsoft.com/en-us/dotnet/fsharp/language-reference/query-expressions) 支持 LINQ 风格查询，但来源控制其含义。

| 来源 | 典型执行位置 | 重要后果 |
|---|---|---|
| `list`、数组、`seq`、CSV 行 | 本地 .NET 枚举 | 可以使用 F# 函数，但 CPU 与数据移动由你承担 |
| 来自 EF 或其他提供程序的 `IQueryable<'T>` | 由提供程序翻译表达式树 | 只有受支持的表达式可翻译；适用 SQL 与提供程序语义 |
| 取得完整结果后接 `Seq` | 先远程，后本地 | 取得完整结果的位置决定数据传输边界 |
| 异步流 | 增量本地副作用 | 取消、释放、背压与部分失败都很重要 |

因此相同外观的 `where` 可能表示本地谓词，也可能表示提供程序表达式。不受支持的翻译会抛错；不同提供程序版本可能给出不同翻译；数据库的空值、排序规则、小数、日期与排序语义也可能不同于 .NET。

用命名和测试标出执行边界。对重要查询检查生成的 SQL 或提供程序诊断；只投影必需列，限制结果大小并传递取消。方言或事务行为重要时，要针对真实数据库引擎测试。内存提供程序无法验证生产 SQL。

如果枚举会执行 I/O，就不要把远程查询藏在看似普通的 `seq<'T>` 后面。`search : Query -> CancellationToken -> Task<SearchResult list>` 这样的端口能明确表示外部操作、完整结果的生成位置与取消边界。

## 按控制需求与 schema 责任选择关系访问方案 {#relational-access}

F# 可以使用完整的 .NET 数据库生态。关键不在于“F# 库还是 C# 库”，而在于每种方案会处理多少 SQL、映射、跟踪、schema 发现与生命周期工作。

### 直接使用 ADO.NET 提供程序 {#ado-net}

需要直接控制 SQL、流式处理、批量操作、提供程序特性或依赖数量时，使用供应商的 `DbConnection`、参数化 `DbCommand` 与读取器。映射、空值处理、事务、释放、重试和诊断由你负责。这些代码通常适合放进职责单一的适配器，与哪种写法“更高尚”无关。

绝不要用插值把不受信值拼进 SQL。参数能保护值；动态标识符和查询结构需要允许列表或查询构建器。尽可能晚地打开连接，确定性释放读取器与命令，并向异步操作传递取消。

### Dapper {#dapper}

[Dapper 2.1.79](https://www.nuget.org/packages/Dapper/2.1.79) 是 ADO.NET 之上的 SQL 优先对象映射器。它能减少重复的参数和行映射，同时让查询文本保持可见，并明确事务由谁控制。

它适合读模型，以及希望直接掌控 SQL 的服务团队。F# 摩擦会出现在构造函数、匿名参数、选项、记录与空值处；可用 CLR 友好的持久化 DTO 和小型映射函数将其限制在适配层。Dapper 不会替你设计聚合、迁移、并发规则或安全 SQL 组合。

### Entity Framework Core {#ef-core}

EF Core 提供更完整的工作单元、变更跟踪、关系、LINQ 翻译、迁移与提供程序模型。[EF Core 10](https://learn.microsoft.com/en-us/ef/core/what-is-new/ef-core-10.0/whatsnew) 属于 .NET 10 LTS 产品线，并要求 .NET 10 运行时。

只有 EF Core 的变更跟踪、迁移和查询能力确实减少了整体工作时，才选择它。F# 可以直接调用 EF Core，但其可变实体、导航属性、特性、代理和许多示例都偏向 C# 写法。因此，EF 实体通常更适合留在基础设施层，再映射成不可变的 F# 记录或联合。不要为了方便跟踪数据库变化而削弱业务模型。

### SQLProvider {#sqlprovider}

[SQLProvider 1.5.27](https://www.nuget.org/packages/SQLProvider/1.5.27) 是 F# 数据库类型提供程序，具有 LINQ 查询、模式探索、CRUD、多种数据库后端与离线模式选项。当数据库模式稳定且提供程序支持与目标匹配时，它能给出优秀反馈。

采用前应做一个容易删除的小型试验（spike），并使用真实数据库驱动。试验要覆盖设计期如何取得模式、生成的 SQL、空值、事务、异步和取消，还要检查迁移、发布输出和 CI 还原。生成的实体仍应限制在适配器中。包大小、数据库驱动和原生依赖只是需要评估的部署成本，不能单独说明工具好或坏。

### 比较各方案负责什么 {#relational-comparison}

| 需求 | 首选候选 | 关键验证 |
|---|---|---|
| 直接控制 SQL 与使用提供程序特性 | 直接 ADO.NET | 映射、生命周期、取消、事务与注入测试 |
| 显式 SQL 且减少映射样板 | Dapper | F# DTO 映射、参数化、多重映射与事务行为 |
| 变更跟踪与丰富应用模型 | EF Core | 真实提供程序翻译、并发、迁移与实体/领域分离 |
| 编译期、由 schema 驱动的 F# 访问 | SQLProvider | 可重复获取 schema、生成 SQL、驱动与部署兼容性 |

同一服务可以使用写入导向适配器与独立读取投影。若没有清晰边界，不要让两个库共同协调同一事务或迁移路径。

## 分离事务与领域决策 {#transactions-domain}

数据库库提供机制，业务含义由应用定义。把唯一性、容量、版本检查或账本余额放进真正保护它们的原子操作。把唯一约束违反与乐观并发冲突映射为已声明的应用结果，而不是泄漏供应商异常。

重试需要幂等与事务知识。重试只读瞬态失败，不同于提交期间连接中断后重试命令。用有界标签测量连接池饱和、查询耗时、返回行数、重试与冲突；默认不要记录完整 SQL 参数或行内容。

迁移时要分开“应用可读取两种结构”“模式已改变”“旧写入方已停止”与“旧列已删除”。重新编译类型提供程序和生成 ORM 迁移文件，都不足以验证滚动部署兼容性。

## 根据操作与规模选择分析结构 {#analytical-structures}

当行数有界且操作类型稳定时，从普通 F# 集合开始。数组提供紧凑索引存储；序列支持延迟管道；列表很适合递归构造，但通常不是密集数值表的最佳选择。

[Deedle 8.0.0](https://www.nuget.org/packages/Deedle/8.0.0) 以 `net10.0` 为目标，提供带标签序列与数据帧、对齐、连接、缺失数据操作、分组、统计和时间序列函数。当这些语义真正减少工作时选择它，而不是让每个 CSV 都变成数据帧。

数据帧牺牲一部分静态行类型信息，换取异构列和交互式操作。要明确指定键、重复处理、对齐、缺失值、顺序与转换。一个打印漂亮的数据帧仍可能含有 `object` 列、静默强制转换或错位时间序列。

当数据可能超出内存预算时，不要先把全部内容加载进进程。可以让数据库或分析引擎完成筛选和聚合，也可以分区处理，或使用合适的列式格式。用接近真实规模的数据测量解析、内存分配、连接和序列化。序列是“惰性”的，并不表示分组、排序、缓存或生成完整结果时仍只占固定内存。

## 让探索可复现 {#reproducible-exploration}

SDK 自带 [F# Interactive](https://learn.microsoft.com/en-us/dotnet/fsharp/tools/fsharp-interactive/)：`dotnet fsi` 可运行 REPL 或版本化 `.fsx` 脚本。它是很好的草稿工具，因为语言与运行时相同，但交互式会话仍携带隐藏状态。

为了得到持久结果，应记录：

- 具体的 SDK、包版本与锁定信息；
- 不可变输入标识、模式版本与允许的获取步骤；
- 区域性、时区、文本编码与缺失值策略；
- 随机种子与确定性限制；
- 单元格或步骤执行顺序；
- 预期表格、指标或产物哈希；
- 从干净进程复现结果的非交互命令。

把可复用解析、特征和计算迁移到带测试的编译模块。脚本中只保留编排与呈现。如果分析改变产品决定，就像审阅应用代码一样审阅它。

旧资料经常推荐 Polyglot Notebooks 或 .NET Interactive。Microsoft 已分别在 2026-03-27 和 2026-04-24 [弃用这两个工具](https://github.com/dotnet/interactive/issues/4163)。相关仓库已经归档；现有安装可能暂时工作，但不会再获得新功能或弃用后的安全修复。不要把它们作为新项目默认值。若必须使用 notebook，应单独评估仍在维护的 Jupyter 内核。

## 把可视化视为输出边界 {#visualization}

[Plotly.NET 5.1.0](https://www.nuget.org/packages/Plotly.NET/5.1.0) 是已核对的稳定包；核对日的 6.0 包仍是预发布版。它从 .NET 构建 plotly.js 图表描述，并有相关交互与图像导出包。

图表选择不只包括构造函数：

- 交互 HTML，还是确定的静态图像或矢量导出；
- 浏览器/CDN 策略、离线资源、内容安全策略与包大小；
- 颜色、标签、单位、时区、聚合与不确定性；
- 可访问标题、文字摘要、表格替代、对比度与键盘行为；
- 工具提示、嵌入数据、文件名或导出元数据是否暴露敏感行；
- 服务器、桌面、notebook 或浏览器渲染及其原生/运行时依赖。

先测试图表的数据表，再测试像素。把选择分箱、分母、平滑和缺失值的转换与渲染分离。一张看起来可信的图表，也可能用完美排版呈现错误的总体数据。

## 选择机器学习边界，而不仅是训练器 {#machine-learning}

首先决定任务与产品决策。分类、回归、排序、推荐、异常检测、预测、向量相似度检索与生成具有不同标签、指标、延迟和失败成本。对于已有数据，规则基线可能更便宜、更可解释，也更准确。

完整的训练工作流包括：

```text
版本化观察
  -> 防泄漏切分
  -> 拟合预处理与特征
  -> 基线与候选训练
  -> 适合任务的评估
  -> 不可变模型加模式/元数据
  -> 部署验证
  -> 受监控推理与再训练决定
```

在拟合会从数据学习的转换之前先切分。当随机按行切分会把未来或同一客户泄漏到不同集合时，要保留实体或时间边界。报告与产品成本相关的指标、不确定性与基线；没有数据切片和阈值的“准确率提高”并不完整。

### ML.NET {#mlnet}

[ML.NET](https://learn.microsoft.com/en-us/dotnet/machine-learning/mldotnet-api) 提供 .NET 数据视图、转换、训练器、评估、模型持久化，以及 ONNX 和 TensorFlow 等导入路径。[Microsoft.ML 5.0.0](https://www.nuget.org/packages/Microsoft.ML/5.0.0) 是已核对的稳定包；核对日的 6.0 仍是预发布版。

如果经典机器学习必须在 .NET 进程中训练或推理，ML.NET 是一个候选。F# 能调用它的 CLR API，但这些 API 常使用特性、可变输入输出类和泛型重载，示例也多采用 C# 风格。可以把这些类型限制在 ML 适配器中，再从验证过的 F# 特征记录进行转换。测试保存后的模型时，要在新进程中重新加载，不能只测试刚训练完的内存对象。

### ONNX Runtime {#onnx-runtime}

当训练发生在别处、产品需要可移植推理时，[ONNX Runtime 的 .NET 绑定](https://onnxruntime.ai/docs/get-started/with-csharp.html) 是候选。边界包括模型具名张量、数据类型、维度、预处理、输出解释与执行提供程序，不只是一项 `Run` 调用。

锁定模型摘要和运行时/原生包，推理前验证张量形状，并按文档规定的生命周期与释放责任复用会话和缓冲区。还要限制并发，并在每种目标架构上测试。ONNX 文件属于可执行供应链输入，应像代码一样审阅与分发。

### TorchSharp 或外部训练栈 {#torchsharp-external}

[TorchSharp 0.107.0](https://www.nuget.org/packages/TorchSharp/0.107.0) 向 .NET 暴露 LibTorch 引擎，适合必须留在 .NET 中的张量与深度学习工作。采用它时，原生 CPU/GPU 包、架构支持、张量释放和设备放置都成为运维责任；还要管理可复现性与 1.0 前 API 生命周期。

如果外部 Python 或托管训练平台的算法、硬件工具、实验跟踪或团队经验明显占优，就选择它。通过版本化文件、ONNX、批任务、队列或服务契约保持边界显式。跨进程往往比为整个快速演进生态维护私有 F# 包装器更简单。

### 分离训练与服务 {#training-serving}

| 关注点 | 训练 | 在线推理 |
|---|---|---|
| 主要目标 | 学习与比较 | 在延迟/错误预算下稳定决策 |
| 数据 | 带标签的版本化历史集合 | 一个请求或含已验证特征的有界批次 |
| 生命周期 | 迭代、资源密集，通常离线 | 长生命周期模型/会话与受控并发 |
| 验证 | 切分、基线、指标、种子、来源 | 启动加载、模式兼容、负载、失败、回滚 |
| 监控 | 实验与数据质量 | 延迟、错误、特征/模型漂移、决策结果 |

不要在 Web 启动期间训练，也不要为每个请求构造预测引擎，除非测量结果和生命周期要求支持这种设计。预热模型，定义线程安全，在诊断中显示版本，并保留上一份不可变产物用于回滚。

## 开展范围受限的数据栈试验 {#adoption-spike}

用相同验收数据验证一条代表路径：

- 覆盖空值、Unicode、时间、小数与边界值的真实模式；
- 一条有界且经过投影、筛选、排序的成功查询，以及格式错误、取消、依赖/瞬态失败和适用的写冲突或事务边界；
- 代表规模下的生成 SQL、分配、行数与延迟；
- 从锁定还原到目标平台执行，并审阅机密、日志、临时文件、可视化输出与模型产物；
- 一次升级或模式演进和明确的删除条件。

先比较正确性与维护责任，再比较语法。一个依赖实时开发数据库、在线下载模式、加载全部行或隐藏原生运行时的十行演示并不更简单；它只是把工作移出了文件。

## 练习 {#exercises}

### 练习 1：选择三个数据边界 {#exercise-01}

分别评估以下数据工作负载：

1. F# 预约服务需要事务写入、乐观并发和五条精心调优的 PostgreSQL 查询。
2. 分析师按日期连接三个有界 CSV 导出、探索缺失值，并每周发布一张可访问图表。
3. Web API 接收版本化特征 DTO，必须在同一进程内于 30 ms 内运行由 Python 团队训练的模型。

为每项工作负载选择并论证首选候选，至少比较两个选项，再列出会让选择反转的证据。


::: details 参考答案

#### 情况 A：事务型 PostgreSQL 预约数据 {#exercise-01-case-a}

先在一个基础设施适配器内使用供应商 ADO.NET 提供程序与 [Dapper 2.1.79](https://www.nuget.org/packages/Dapper/2.1.79)。五条已调优 SQL 保持可见，再把持久化 DTO 映射到现有预约领域。

应用端口应描述持久化操作，而不是查询机制：

```fsharp
type BookingStore =
    { TryAppend:
        expectedVersion: int64 ->
        events: BookingEvent list ->
        CancellationToken ->
        Task<Result<int64, AppendError>> }
```

事务加载或检查当前版本，再执行类似 `WHERE version = @expectedVersion` 的条件写入。零条受影响行映射为 `VersionConflict`，唯一约束冲突映射为规定的重复结果。提交结果不明时，不得盲目重试。实际 SQL 取决于模式与驱动，因此要在生产使用的同一 PostgreSQL 大版本上测试。

直接 ADO.NET 是备选。如果流式处理、批量操作、提供程序专属类型或映射控制让 Dapper 的帮助很小，它可能更合适。只有变更跟踪、迁移或 EF Core 应用模型带来可测价值时，才考虑 EF Core 10。五条调优查询和明确的事件/版本语义，并不足以支持使用跟踪实体。

试验必须验证：

- 每个值都参数化，任何动态标识符都来自允许列表；
- 事务范围与释放责任清楚，连接和读取器都得到释放；
- 取消传到打开、执行与读取操作；
- 五条查询返回有界投影并使用预期索引；
- 两个受控写入方使用同一期望版本时，得到一个成功与一个冲突；
- 提交附近连接丢失会产生已定义的对账或幂等停点；
- SQL 诊断暴露耗时与行数，但不记录敏感参数；
- 锁定还原、迁移、发布、启动与回滚在目标环境工作。

如果 Dapper 让记录或空值映射更复杂，或没有持续价值，就选择直接 ADO.NET。若代表性写入与查询表明 EF Core 工作单元和迁移能减少整体实现与维护成本，则可选择 EF Core；但实体不能泄漏进领域。

#### 情况 B：每周 CSV 分析与可访问图表 {#exercise-01-case-b}

从 FSharp.Data 有界摄取、[Deedle 8.0.0](https://www.nuget.org/packages/Deedle/8.0.0) 日期键对齐与缺失数据处理开始，并只在渲染边界使用 [Plotly.NET 5.1.0](https://www.nuget.org/packages/Plotly.NET/5.1.0)。

先比较 Deedle 与记录加 `Map<DateOnly, _>`。若三个小文件只有一个唯一日期键和两次连接，类型化映射可能更清楚，行字段也直接体现在类型中。当重复外连接、对齐、重采样与缺失值策略主导分析时，暂定选择 Deedle。

每周任务应当：

- 锁定三个合成模式样本，并分别验证每个运行期文件；
- 记录输入摘要、获取时间、区域性、编码与预期日期范围；
- 拒绝重复键，或按一条有文档的规则解决；
- 区分缺失观察、零与无效单元格；
- 在已编译且测试过的函数中计算图表数据表；
- 随图表一同输出 CSV 数据表与文字摘要；
- 明确写出单位、时区、分母、颜色与可访问标签；
- 打包或批准浏览器资源，并扫描 HTML/工具提示中的敏感数据；
- 从干净进程无界面运行，并比较不变汇总值。

若 Plotly.NET 无法稳定导出交付所需的静态格式，或浏览器策略拒绝其资源，就淘汰它。若更简单的报表工具已经处理可访问性和分发，也应优先用该工具。分析计算仍可保留，因为它不返回图表对象。

#### 情况 C：Python 训练模型与本地 30 ms 推理 {#exercise-01-case-c}

从 ONNX 导出和 [ONNX Runtime .NET 绑定](https://onnxruntime.ai/docs/get-started/with-csharp.html) 开始。它保留 Python 团队的训练生态，同时让推理留在进程内并避免网络跳转。

在 HTTP 输入处定义带版本的 `FeatureDto`，验证后映射为中立 `FeatureVector`。一个推理适配器集中管理张量名称与顺序、数据类型、维度、归一化、会话、执行提供程序，以及输出到决策的映射。不要让张量对象或模型专属列名进入领域。

验收条件包括：

- Python 与 .NET 路径运行同一组黄金向量，并在已声明容差内一致；
- 模型摘要、opset、特征模式、预处理版本、标签、阈值与训练数据标识一同传递；
- 新进程在就绪成功前加载并预热不可变模型；
- 维度无效、`NaN`、无穷值、特征缺失与未知模式版本在推理前失败；
- 有界并发负载测试在每种目标架构满足 30 ms 百分位预算；
- 原生运行时包被锁定、发布、漏洞审阅，并在部署镜像中执行；
- 诊断报告模型版本、延迟与有界结果，而不是原始特征；
- 上一产物仍可部署，回滚不需要模式降级。

ML.NET 是备选，因为它能导入 ONNX 并加入 .NET 转换。只有这些转换减少了团队要维护的预处理代码，且黄金向量仍一致时，它才更合适。本地 Python sidecar 暂不选择，因为在没有明确需求时，它会重新引入进程启动、打包、序列化与健康检查。

:::

### 练习 2：为 CSV 模式漂移设计 {#exercise-02}

供应商对 CSV 做了以下修改：把 `UnitPrice` 改成 `Price`，加入 `Currency`，允许 `OrderedAt` 为空，并且可能增加未知列。请设计同时接收 v1 和 v2 的边界，并说明：

- 两个版本各使用什么编译期样本；
- 如何解析语法并映射到源 DTO；
- 哪些变化兼容，哪些必须拒绝；
- 业务验证和隔离记录保存什么；
- 测试哪些输入；
- 什么时候可以删除 v1 支持。

货币不同的两个小数不能直接相加，因此不要把 `Currency` 当成无关字段。


::: details 参考答案

#### 明确识别版本 {#exercise-02-recognition}

不要替换数据样例后就假设所有生产方已经原子切换。定义两个源契约，并根据封套版本、清单、由接收方控制的文件名约定或有界表头检查选择。只有区分列集合不可能重叠时，表头猜测才可作为后备。

| 源契约 | 必需列 | 可选/扩展规则 |
|---|---|---|
| v1 | `OrderId,Region,Product,Units,UnitPrice,OrderedAt` | 未知列遵循明确的忽略或拒绝策略 |
| v2 | `OrderId,Region,Product,Units,Price,Currency` 加 `OrderedAt` | 语法上允许空白 `OrderedAt`；未知列使用同一已声明策略 |

为每个接受版本保留一个小型合成编译期样本。v2 样本必须包含空白日期，并有足够的代表值来推断预期的可选数值与日期类型。类型提供程序生成的类型只留在私有 `V1Adapter` 与 `V2Adapter` 中。

如果上游频繁变化或表头确实开放，就用明确的 CSV 模式与解析器替换样本派生的运行期解码，同时把样本保留为测试数据。类型提供程序只是可选的便利工具，不是兼容性契约来源。

#### 通过源 DTO 规范化 {#exercise-02-normalization}

使用这个边界：

```text
有界 UTF-8 CSV
  -> 已识别的 v1 或 v2 源行
  -> 语法与列诊断
  -> 版本专属规范化
  -> 领域验证
  -> 已接受行或隔离记录
```

只有把 `Currency` 按允许的 ISO 货币集合解析后，`Price` 才成为金额候选。对于 v1，只有供应商契约保证时，才使用 USD 等版本化配置货币；否则 v1 无法安全构造金额，必须拒绝或转入补全。绝不要相加不同货币的小数。

空白 v2 `OrderedAt` 在源 DTO 中映射为 `None`。领域再决定是否允许缺失、是否用可信消息封装中的时间戳替代，或是否拒绝。非空但无效的日期不是 `None`，而是格式错误。

使用其他适配器共用的构造器规范化 `OrderId`、地区、数量与产品。在产生副作用前检测文件内重复订单 ID。把行号、源版本、安全错误代码与输入摘要写入隔离记录。应用日志不得包含完整敏感行。

对于封闭契约，未知列应拒绝；对于扩展容忍契约，则忽略并记录。两个版本都应用同一策略。根据提供程序行为静默切换会让兼容性变成偶然。

#### 建立兼容性样例集 {#exercise-02-evidence}

样例集应覆盖：

- 当前 v1 与 v2 样本；
- 在文档明确货币的前提下，v1 `UnitPrice` 与 v2 `Price` 映射到相同金额；
- 缺失、空白、格式错误、重复与大小写不同的表头；
- 空白和无效 `OrderedAt`；
- 受支持、缺失、未知和大小写错误的货币代码；
- 零、负数、溢出与高边界数量/价格；
- 带引号逗号、引号、CRLF/LF、Unicode、BOM、无效 UTF-8 与大小/行数上限；
- 允许和禁止的未知列；
- 不得部分提交的混合或歧义文件；
- 提交前取消，以及隔离后的确定性重试。

在无网络的干净锁定构建中编译两个适配器。让它们规范化后接受的行运行同一套下游契约测试。用有界标签观察各源版本的接受/拒绝计数。

满足以下全部条件后，才能删除 v1：

- 供应商契约与迁移窗口已经结束；
- 在约定保留期内，生产未再收到 v1 输入；
- 留存重放不再需要 v1；
- 所有调用方与测试样例都已迁移；
- 回滚不会恢复发送 v1 的生产方。

即使删除可执行支持，也要保留迁移决定与去敏的模式样例。

:::

### 练习 3：把探索模型生产化 {#exercise-03}

一个 `.fsx` 脚本会加载本地数据、构造特征、训练分类器、打印准确率并绘图。请设计一条改造路径，把它拆成可重复运行的训练任务和可独立部署的推理组件。方案至少要说明：

- 如何标识不可变的训练数据，并防止训练集与测试集互相泄漏；
- 使用什么基线、总体指标和分组指标；
- 如何锁定包、模型和特征格式；
- 如何处理机密并进行无界面测试；
- 模型登记时保存哪些信息；
- 如何验证启动和负载；
- 如何监控并回滚模型。


::: details 参考答案

#### 固定问题与数据血缘 {#exercise-03-lineage}

选择算法前，写清产品决定、预测范围、标签定义、观察单位、排除用途和误报/漏报成本。创建只读数据清单，包含源版本、抽取查询或任务修订、时间范围、行数、模式摘要、内容/对象版本与访问策略。

绝不要把实时生产导出复制进源码控制。把它存入获批不可变位置；仓库中只保留微型合成样例。训练任务接收清单标识，而不是“latest.csv”。

按因果单位切分。对于重复客户、设备或事件，让同一实体只位于一侧。对于预测，用过去训练，并在更晚时间区间验证。只在训练数据上拟合插补器、编码器、缩放、特征选择与词表，再把已拟合转换应用到验证与测试集。

#### 提取经过测试的特征管道 {#exercise-03-features}

把解析、验证、特征派生与指标计算从 `.fsx` 文件移入编译项目。为已验证观察定义数据记录与版本化特征模式。单元测试边界值，并添加与推理共享的黄金向量测试。

迁移期间只把脚本保留为薄调用方；若继续保留，则从干净进程用 `dotnet fsi` 运行。不要在 .NET Interactive 或 Polyglot Notebooks 上建立新工作流：两者都已弃用且项目已归档。如果仍维护的 notebook 前端对呈现有用，它应调用相同编译管道，并且不能成为唯一可执行记录。

#### 不可变地训练、评估与打包 {#exercise-03-training}

无界面训练命令锁定 SDK/包，并记录代码修订、数据清单、切分定义、种子、确定性限制、特征版本、训练器/超参数、运行时/架构与资源耗时。它训练简单基线与候选模型。

报告适合任务的指标，包括置信度或重复运行变化、决策阈值、相关时的校准，以及重要群组/时间范围切片。与基线和产品成本比较。即使总体改善，只要必需切片退化就拒绝晋级。

晋级产物包含：

- 不可变模型字节与密码学摘要；
- 模型格式/opset 及必需运行时/原生包版本；
- 有序特征/输出模式、数据类型、维度、标签与阈值；
- 预处理产物或指定的特征代码版本；
- 训练数据清单、代码修订、指标、切片与批准；
- 许可证、安全、预期用途、限制与到期/复核元数据。

当训练与服务有意共享 ML.NET 管道时，选择 ML.NET 模型。若系统需要稳定承接 Python 训练器的可移植产物，则选择 ONNX。转换必须用黄金向量与代表批次测试，不能只因导出成功就接受。

#### 明确推理组件的职责 {#exercise-03-inference}

启动时加载配置指定的模型，验证摘要与模式，创建长生命周期会话或引擎，并在预热后报告就绪。请求路径验证特征 DTO，应用匹配的预处理版本，再调用有并发上限的执行池。最后把输出映射为规定的决策，且不记录原始敏感特征。

契约测试覆盖模式版本、黄金预测、阈值、无效浮点值、超时与取消、模型损坏或缺失、原生库失败与安全错误。负载测试在每种 CPU 或 GPU 架构的部署镜像中运行。真实进程冒烟测试验证发布布局与启动生命周期。

以保护隐私的有界维度监控输入有效性、缺失度、特征范围、预测分布、延迟、故障、模型版本与延迟决策结果。漂移是调查信号，不是自动再训练命令。

策略允许时，通过影子或金丝雀流量比较新不可变产物。选择上一模型或服务产物即可回滚；回滚窗口内要保持输入兼容。再训练必须经过相同的评估与批准门，不能只因时间戳更新就部署。

原始图表成为可复现的审阅输出，并附带源数据表与文字摘要。它永远不能成为晋级的唯一依据。
