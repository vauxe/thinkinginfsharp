# 附录 H：高级特性识别索引 {#overview}

本附录帮助你在陌生代码中识别四类 F# 特性、先问最关键的问题，并找到可靠资料。这些特性都不是日常 F# 编程的前置知识。

基础仍是函数、类型、模式、模块、集合、受控副作用、async/task、.NET 互操作与测试。只有 API、性能分析结果、库或必要抽象确实要求某项高级特性时，才需要深入学习。

## 快速识别表 {#quick-map}

| 特性 | 识别线索 | 核心思想 | 先问什么 |
|---|---|---|---|
| 代码引用（quotations） | `<@ ... @>`、`<@@ ... @@>`、`Expr<'T>`、代码引用模式 | 把 F# 表达式表示成数据 | 代码是在构造、转换、翻译还是执行表达式树？ |
| 静态解析的类型参数（SRTP） | `inline` 加静态/成员约束；当前简化签名中的 `'T`，或旧式/复杂形式中的 `^T` | 在编译期解析所需成员并特化 | 为什么普通泛型、接口或具体重载不能清楚表达它？ |
| 灵活类型 | 类型表达式内部的 `#BaseType` | 在嵌套/高阶位置接受任意子类型或接口实现 | 普通参数向上转型是否已经有效，更通用签名是否值得暴露？ |
| byref/Span | `&value`、`byref`、`inref`、`outref`、`Span`、`ReadOnlySpan` | 使用受栈约束的托管引用与连续内存视图 | 实际测量发现了哪项复制开销，或哪个互操作 API 要求承担这些生命周期限制？ |

不要只从标点推断含义。同一符号还会出现在别处：`#` 可开始 FSI 指令，`^` 可出现在旧式 SRTP 语法和运算符中，`&` 也可出现在成员约束和布尔运算符中。只有以 `<@` 开始的代码引用才表示下面介绍的含义。

## 代码引用（quotations）：把代码表示为表达式数据 {#quotations}

有类型代码引用使用 `<@ expression @>`，类型为 `Expr<'T>`；无类型代码引用使用 `<@@ expression @@>`，类型为 `Expr`。编译器会建立表示该表达式的对象树，而不是在当前位置直接执行表达式。

识别信号包括：

- `open Microsoft.FSharp.Quotations`；
- `Expr<'T>` 或 `Expr` 值；
- 来自 `Microsoft.FSharp.Quotations.Patterns`、`DerivedPatterns` 或 `ExprShape` 的模式；
- 另一段代码引用内的拼接（splice）运算符 `%` 与 `%%`；
- 为查询、DSL、翻译、分析或生成而接受表达式树的库 API。

首先要区分“表示代码”和“执行代码”。代码引用不会自行执行；求值器、翻译器、类型提供程序或其他使用方会解释这棵树，而且可能只支持部分表达式形式。

只有调用方确实需要把代码当作数据检查时，才使用代码引用。例如，类型化查询翻译器需要读取属性访问与比较。不要只因表达式树看起来更强大，就把普通回调包进代码引用；调用方只需执行逻辑时，函数更简单。

评审：

- 使用方接受哪些表达式节点，不支持的节点如何失败；
- 捕获值是嵌入、参数化、序列化还是拒绝；
- 求值发生在本地、远端、生成代码中，还是根本不发生；
- 代码引用是否跨越版本、进程、信任、裁剪或 AOT 边界；
- 诊断能否指回有用源码位置。

遍历表达式树时，第 15 章介绍的活动模式很有帮助。[第 40 章](../part-07/ch-40-data-analytics)说明数据和查询工具为何会提供类型化表达式树 API，而无需每位用户都编写代码引用处理器。

## 静态解析的类型参数（SRTP）：编译期成员约束 {#srtp}

静态解析的类型参数让内联函数要求普通 .NET 泛型约束无法表达的成员。F# 会在编译期解析所需成员，并为具体调用生成特化代码。

当前 F# 简化语法通常会打印 `'T` 这样的撇号前缀参数，即使它们带 SRTP 约束。文档与复杂的显式分派代码仍可能使用 `^T` 这样的脱字符形式。因此，应通过以下组合识别 SRTP：

- `inline` 函数或成员；
- 静态或实例成员约束；
- 调用点处的运算符/成员解析；
- 特化，而不是一份普通泛型方法体。

常见入口是数值运算符和小型成员抽象。许多 FSharp.Core 运算符已经使用 SRTP；调用它们不意味着你也需要编写自定义 SRTP 抽象。

引入 SRTP 前，应比较：

- 更直接表达领域的具体类型；
- 没有成员要求的普通泛型函数；
- 显式传入的接口、委托或操作记录；
- 少量命名重载；
- 当目标 API 本来就使用泛型数学时，采用当前 .NET 泛型数学接口。

SRTP 可能让推断签名更复杂、复制特化代码、增加编译时间、让公共 API 更难使用，并使类型推断更难预测。把它限制在局部，检查推断类型，测试每个预期的具体类型，并避免公开由实现细节带来的约束。

[第 11 章](../part-02/ch-11-generics-constraints)解释普通泛型、相等/比较约束与 SRTP 的区别。正文采用 F# 7+ 的简化语法，不会只凭 `^T` 这一种写法判断是否为 SRTP。

## 灵活类型：类型表达式中的子类型兼容 {#flexible-types}

`#SomeType` 是灵活类型标注。从概念上说，它等价于带 `:> SomeType` 约束的新泛型类型。当兼容类型出现在高阶或嵌套类型位置，且自动向上转型不会发生时，它尤其有用。

例如，签名可以接受返回 `#seq<'T>` 的函数，这样调用方可以返回列表、数组或其他序列实现，无需明确写向上转型。

识别问题包括：

- `#` 是否位于类型标注内，而不是 FSI 指令开头？
- 哪个基类或接口建立兼容性？
- 灵活类型是否嵌套在函数、集合或另一泛型位置？
- 更通用的输入类型是否真的方便调用方，还是只让推断签名更难解释？

普通自动转换已经有效时，优先使用直接的参数类型。如果具名泛型约束能让公共 API 或实现更易读，就明确写出约束。灵活类型只是一种简写，不会产生不同的运行时表示。

## Byref 与 Span：面向互操作和缓冲区的受限生命周期 {#byref-span}

`byref<'T>`、`inref<'T>` 与 `outref<'T>` 是分别用于读写、只读和写出参数的托管引用类型。`Span<'T>` 与 `ReadOnlySpan<'T>` 是连续内存上的 byref-like 视图。编译器限制它们的逸出和捕获，防止其生命周期超过所引用的存储。

识别信号包括：

- 传递或保留托管引用时的 `&value`；
- 含 `byref`、`inref` 或 `outref` 的参数或返回；
- `Span`、`ReadOnlySpan` 或标记为 `IsByRefLike` 的类型；
- 无法把值捕获进闭包、对象字段或异步工作流的代码；
- 对已经使用 span 或引用的 .NET API 直接适配。

只在同步代码中使用这些类型，而且应有明确理由：测量表明需要避免切片或复制、需要解析热点缓冲区，或现有 API 要求这样做。长期存活或异步代码仍应使用数组、列表、记录或 `Memory<'T>` 等类型。

检查谁持有底层存储、哪些代码可以修改或别名引用它、如何处理空值与 `default`、索引范围、引用何时失效，以及调用后的行为。`inref` 只限制持有该引用的代码，不能证明其他别名不会修改同一个值。

F# 的限制与互操作支持会随版本变化。请核对语言版本和当前官方页面，不要照搬旧的变通写法。[第 31 章](../part-05/ch-31-measure-before-optimizing)说明如何先分析性能再选择数据表示；本附录只帮助识别语法。

## 本版有意不教授的特性 {#scope-boundary}

本版不教授：

- 编写类型提供程序；
- 基于 FSharp.Compiler.Service 构建工具；
- 编写通用代码引用求值器或编译器；
- 高级 SRTP 分派框架；
- 编写自定义 byref-like 数据结构；
- 在没有测量或互操作需求时使用底层特性。

只要理解公开 API，你仍然可以使用类型提供程序、编译器驱动工具、查询库、数值抽象或基于 Span 的 .NET API。“这里不教”只表示这些实现主题需要单独的指南，并应针对具体版本、依据官方资料讲解；并不表示这些能力不值得使用。

## 安全阅读顺序 {#reading-sequence}

陌生高级代码阻碍进展时：

1. 写下能说明问题的最小公开类型签名；
2. 判断该特性是在表示代码、解析成员、放宽子类型输入，还是约束内存生命周期；
3. 阅读所链接的官方参考，核对所用语言版本；
4. 制作一个可执行示例，并保留一个失败或拒绝案例；
5. 找到该特性位于系统哪一层、由谁调用；
6. 决定深入学习实现、包装它，还是把它留在库适配器后；
7. 相关时记录目标、版本、性能、裁剪/AOT 与互操作验证结果。

返回[第 45 章](../part-07/ch-45-scripting-packages-next)查看更完整的学习路线与包选择方法。高级知识只有用来回答可验证的系统问题时，才最有用。
